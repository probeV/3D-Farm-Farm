# PRD — 3D Farm Farm (쓰리디팜팜)

> 데이터 구조: [ERD.md](ERD.md) · 화면: [screens.md](screens.md)

## 1. 개요

### 목적
3D 프린터로 만든 제품(수업 교구 등)을 네이버 스마트스토어에서 판매할 때 필요한
**제품별 원가·마진 계산**과 **필라멘트 스풀 재고 관리**를 한곳에서 한다.

### 해결하려는 문제
- 스프레드시트로는 부자재·수수료까지 반영한 실제 마진을 알기 어렵다.
- 필라멘트 가격이 바뀌면 관련 제품 원가를 일일이 고쳐야 한다.
- 회사·재질·색상별 스풀 재고와 사용량을 파악하기 어렵다.

### 사용자 / 사용 환경
- 사용자: 1인 판매자
- 내 PC 에서 서버를 켜고 브라우저로 사용. 같은 와이파이의 폰에서도 접속.
- 인터넷에 공개하지 않음 (로그인 없음)

### 기술 스택
| 영역 | 선택 |
|---|---|
| 백엔드 | Python 3.10+, Django 5.2 (LTS), Django REST Framework |
| DB | SQLite (로컬) |
| 프론트엔드 | React + TypeScript + Vite, TanStack Query, Zod (입력 검증) |
| 저장소 구조 | 모노레포 — `backend/` (Django), `frontend/` (React) |

- 화면은 React, 데이터는 DRF JSON API 로 주고받는다. Django 관리자(`/admin`)는 그대로 사용한다.
- 화면 디자인 기준: [mockups/](mockups/) 의 HTML 목업

## 2. 용어집

| 용어 | 뜻 |
|---|---|
| 회사 | 필라멘트 제조사 (예: Bambu Lab, Esun) |
| 재질 | 회사와 상관없는 필라멘트 종류 목록 (예: PLA, PETG, PETG-CF, ABS, TPU) |
| 필라멘트 | 회사 + 재질 + 시리즈(선택) 단위의 제품 (예: Bambu Lab › PLA Matte, Esun › PETG). 기본 스풀 가격·무게를 가진다 |
| 시리즈 | 같은 회사·재질 안에서 구분하는 이름 (예: Basic, Matte, Silk). 없으면 비움 |
| 색상 | 필라멘트 안의 색상 (예: 화이트, `#F5F5F5`). 재고는 색상 단위로 센다. 필라멘트와 다른 가격을 가질 수 있다 |
| 스풀 | 필라멘트 실물 1롤. 1개 = 기록 1개 |
| 스풀 코드 | 스풀마다 붙는 코드 `S00001` (= 스풀 번호 1). DB 내부 번호(id)와 따로 매긴다. 번호는 자동 — 지금까지 쓴 가장 큰 번호 다음 (지운 번호는 다시 안 씀). QR 라벨에 찍힌다 (INV-10) |
| 재고 / 사용 중 / 사용 완료 | 스풀 상태 (`sealed` / `open` / `empty`). 재고 = 아직 뜯지 않은 스풀, 사용 중 = 프린터에 걸어 쓰는 중 |
| 재고 없음 / 소진 | 색상 상태. 재고 없음 = 재고 0개(사용 중만 남음), 소진 = 재고·사용 중 모두 0개 |
| 카테고리 | 제품을 묶는 분류 (예: 수업 교구, 퍼즐). `제품 관리` 창에서 관리. 없으면 미분류 |
| 세부 분류 | 카테고리 안에서 한 번 더 나누는 분류 (예: 수업 교구 › 수학). 선택 |
| 부자재 | 제품에 함께 들어가는 자석, 나사, 포장재 등. 묶음 구매가 ÷ 묶음 수량 = 개당 단가 |
| 원가 | 제품 1개를 만드는 비용 (필라멘트비 + 전기료 + 부자재비) |
| 순이익 | 판매가 − 원가 − 스마트스토어 수수료 − 판매자 부담 배송비 |
| 순마진율 | 순이익 ÷ 판매가 |
| 되돌리기 | 방금 한 동작(재고 추가 · 상태 변경 · 스풀 삭제)을 원래대로 돌리는 것. 처리 직후 알림에서만 가능 |

## 3. 기능

### 3.1 회사 · 재질 · 필라멘트 · 색상 — `FIL`
| ID | 기능 | 상세 |
|---|---|---|
| FIL-01 | 회사 관리 | 이름(중복 불가), 대표 이미지(로고) |
| FIL-01a | 회사 대표 이미지 | png/jpg/webp(5MB 까지) 업로드 → 256×256px 이내로 자동 축소해 저장. 바꾸거나 지우면 이전 파일 삭제. 없으면 회사 이름 첫 글자 아이콘으로 표시 |
| FIL-02 | 재질 관리 | 회사와 상관없는 공통 목록. 이름(중복 불가, 예: PLA, PETG-CF) |
| FIL-03 | 필라멘트 관리 | `필라멘트 관리` 창에서 추가 · 복제(값만, 색상은 복사 안 함) · 수정 · 삭제. 필라멘트 목록의 제목 타일을 눌러도 수정. 회사 선택 + 재질 선택 + 시리즈(선택), 스풀 가격, 스풀 무게(기본 1000g). 회사·재질·시리즈 조합은 중복 불가 |
| FIL-04 | 색상 관리 | 필라멘트 안에서 관리. 이름(같은 필라멘트 안에서 중복 불가), 색상 코드(hex), 가격 |
| FIL-05 | 색상 코드 직접 입력 | hex 값을 글자로 입력·붙여넣기 (`#F5F5F5`, `F5F5F5` 모두 허용 → `#F5F5F5` 로 저장). 입력하면 바로 색 미리보기. 색 선택기도 함께 제공 |
| FIL-06 | 색상별 가격 | 색상 가격을 비우면 필라멘트 가격을 따르고, 입력하면 그 색상만 다른 가격 |
| FIL-07 | 색상 추가 위치 | 필라멘트 목록의 각 필라멘트 묶음 끝 `+ 색상` 타일 → 그 필라멘트로 고정된 색상 추가 창 |
| FIL-10 | 색상 타일 | 필라멘트 목록은 필라멘트마다 묶음 하나: 첫 칸은 제목 타일(로고 · 회사 · 필라멘트 이름 · 스풀 가격, 색상 타일과 구분되게 강조 색 배경. 누르면 필라멘트 수정), 이어서 색상 타일(왼쪽 색 선 · 이름 · 상태 배지 · 보유량 kg[재고 + 사용 중] · 그 색상으로 그린 비율 막대[재고 = 그 색 두꺼운 칸, 사용 중 = 연한 두꺼운 칸, 사용 완료 = 가는 회색 선. 검정·흰색도 보이게 칸마다 얇은 테두리. 스풀이 하나도 없으면 가는 선만] · 재고/사용 중/완료 개수), 마지막에 `+ 색상` 타일. 세 종류 모두 같은 크기이고 넘치면 아래로 줄바꿈 (제목 타일 크기는 그대로). 타일을 누르면 메뉴: 머리(색상 · 코드 · 스풀 수 + 톱니바퀴 = 색상 · 스풀 관리 창) · `재고 추가` · `사용 중으로` · `사용 완료로` |
| FIL-08 | g당 가격 | 색상의 스풀 가격 ÷ 필라멘트의 스풀 무게 |
| FIL-09 | 삭제 제한 | 필라멘트가 있으면 회사·재질, 색상이 있거나 제품에서 쓰면 필라멘트 삭제 불가. 색상은 막지 않고 경고 후 삭제: 그 색상의 스풀도 함께 삭제, 제품에서 쓰던 줄은 `색상 선택 안 함`(필라멘트 가격으로 계산). 함께 바뀌는 것이 있으면 개수를 보여 주고 2차 확인 (되돌리기 없음) |

- 화면 표시 이름: `회사 › 재질 시리즈` (예: `Bambu Lab › PLA Matte`, 시리즈가 없으면 `Esun › PETG`)

### 3.2 회사별 요약 — `SUM`
| ID | 기능 | 상세 |
|---|---|---|
| SUM-01 | 요약 위치 | 필라멘트 화면 맨 위, 필라멘트 목록보다 먼저. 별도 제목 없음 |
| SUM-02 | 표시 대상 · 순서 | 등록된 모든 회사. 사용량(사용 중 + 사용 완료 kg)이 많은 순, 같으면 회사 이름순. 검색·필터와 무관 |
| SUM-03 | 회사별 내용 | 회사 대표 이미지(크게) · 이름, **보유량**(재고 + 사용 중 kg). 카드 전체를 누르면 필라멘트 목록을 그 회사로 필터 (다시 누르면 해제) |
| SUM-04 | 비율 막대 | 재고 · 사용 중 · 사용 완료 무게 비율을 한 줄 막대에 색으로 구분하고, 아래에 상태별 kg 표시 (스풀 수 × 스풀 무게) |
| SUM-05 | 전체 요약 | 재고 스풀 수, 사용 중 스풀 수, 재고 없는 색상 수(주황), 소진된 색상 수(빨강)를 화면 맨 위에 작은 글씨 한 줄로 |
| SUM-06 | 배치 | 카드는 고정 크기. 한 줄에 다 들어가면 1줄, 넘치면 2줄로 나누고 가로로 슬라이드. 스크롤바는 숨기고 좌우 화살표 버튼 · 마우스 끌기 · 휠로 넘김 |

- 사용 중 스풀은 실제 잔량을 알 수 없으므로 무게 전체를 "사용 중"으로 따로 표시한다 (사용·남은 양으로 나누지 않음).

### 3.3 검색 · 정렬 — `FND`
| ID | 기능 | 상세 |
|---|---|---|
| FND-01 | 검색 | 회사 · 재질 · 시리즈 · 색상 이름 |
| FND-02 | 필터 | 회사(전체 / 하나), 재질(전체 / 하나). 회사별 요약 카드의 회사 이름을 눌러도 회사 필터. `필터 지우기` |
| FND-03 | 정렬 | 회사 이름순 / 재고 많은 순(재고+사용 중 kg) / 재고 적은 순 / 전체 많은 순 |
| FND-04 | 적용 범위 | **필라멘트 목록에만** 적용 (회사별 요약·전체 요약은 그대로). 검색·필터·정렬 도구는 "필라멘트 목록" 제목 줄 오른쪽에 둔다 |

### 3.4 스풀 재고 — `INV`
| ID | 기능 | 상세 |
|---|---|---|
| INV-01 | 색상별 재고 | 재고 / 사용 중 / 사용 완료 개수. "재고 없음"(재고 0, 주황), "소진"(재고+사용 중 0, 빨강) 표시 |
| INV-02 | + 재고 (지출 없이) | 지출 없이 들어온 스풀(선물 · 예전 재고)용 — 산 스풀은 필라멘트 지출을 저장하면 생긴다 (EXP-08, v2 TBD-33). 수량(1~100), 구매일(기본 오늘), 스풀 1개 구매가(기본 색상 가격). 스풀 번호는 항상 자동 — 지금까지 쓴 가장 큰 번호 다음부터 (지운 번호는 다시 쓰지 않음, 번호 지정 없음) |
| INV-03 | 사용 중 / 사용 완료 | 처리할 스풀을 코드로 **직접 선택** (자동 선택 없음) |
| INV-04 | 스풀 조정 — 간단 (색상 · 스풀 관리 창의 스풀 탭) | 스풀별 구매가 수정 (지출로 생긴 스풀은 `14,400원 지출` 표시만 — 지출에서 고침), 재고/사용 중/사용 완료 중 선택 (현재 상태는 선택 불가) |
| INV-05 | 스풀 조정 — 세부 | 상태, 구매일 · 사용 시작일 · 사용 완료일, 구매가 수정(지출로 생긴 스풀은 못 함), 스풀 삭제 (확인 문구 · 분실 · 불량 — 지출은 그대로) |
| INV-06 | 페이지 넘김 | 스풀 선택/조정 목록은 10개씩. `‹ ›` 한 페이지, `« »` 5페이지 묶음 |
| INV-07 | 거꾸로 이동 확인 | 사용 완료 → 사용 중, 사용 중 → 재고 등은 확인 문구 후 실행 |
| INV-08 | 보유 스풀 평균 구매가 | 필라멘트별 재고 + 사용 중 스풀의 실제 구매가 평균 |
| INV-09 | 코드로 스풀 조회 | 스풀 코드로 스풀 찾기. 폰 스풀 화면(INV-11)도 이것 |
| INV-10 | QR 라벨 인쇄 (v2 TBD-18) | 필라멘트 화면의 `QR` 버튼. **이미 등록된 스풀로만** 인쇄 (번호 예약 · 새 라벨 없음). 라벨 = QR + 코드 + 색상 · 필라멘트 이름. 라벨을 뽑았는지 스풀마다 기억 — `라벨 없음 N`(기본, 다 쓴 스풀 빼고) · `전체 · 다시 인쇄` 탭, 검색, 맨 위 전체 선택. 크기는 라벨 프린터 40×30 · 50×30mm (한 장씩), 예비로 A4 라벨지 24칸 — 브라우저 인쇄 창에서 프린터를 고름. 인쇄하면 `라벨 뽑음` (취소했으면 알림의 되돌리기). 지출 저장 · 재고 추가로 스풀이 생기면 알림 오른쪽 `라벨 인쇄` → 그 스풀을 골라 둔 채로 |
| INV-11 | 폰으로 찍어 상태 바꾸기 (v2 TBD-18) | 폰 기본 카메라로 라벨을 찍으면 그 스풀 화면이 열림 (앱 설치 없음, QR 안에는 주소 `{PUBLIC_URL}/s/{코드}`). 재고 → `사용 시작` / 사용 중 → `사용 완료` (+ `재고로 되돌리기`) / 사용 완료 → 조회만 (+ `사용 중으로 되돌리기`). 상태는 버튼을 눌러야 바뀜, 날짜 규칙은 아래 그대로. 지운 스풀의 라벨이면 `등록된 스풀이 아니에요`. 등록 · 정보 고치기는 PC 에서만 |

|---|---|---|

| 사용 중 | 없으면 지금 | 지움 |

### 3.5 되돌리기 — `UNDO`
| ID | 기능 | 상세 |
|---|---|---|
| UNDO-01 | 즉시 되돌리기 | 처리 직후 알림의 "되돌리기" 버튼 (7초). 알림이 사라지면 되돌리기 불가 — 이후에는 스풀 조정에서 직접 고친다 |
| UNDO-02 | 되돌리기 방법 | 재고 추가 → 만든 스풀을 지움 / 상태 변경 → 이전 상태·날짜로 / 스풀 삭제 → 같은 번호·내용으로 다시 만듦 / 라벨 인쇄 → `라벨 없음` 으로 |
| UNDO-03 | 나중에 실수를 알았을 때 | 지운 스풀은 재고 추가로 다시 등록 (새 번호 — 지운 번호는 다시 안 씀, 라벨도 새로. 날짜·가격은 다시 입력) |

- 변경 이력은 따로 남기지 않는다. 스풀별 사용 기록은 스풀의 구매일 · 사용 시작일 · 사용 완료일로 확인한다.
- 되돌리기에 필요한 이전 값은 화면이 방금 처리한 결과로 알고 있으므로, 서버에 이력을 저장하지 않는다.

### 3.6 제품 원가 — `PRD`

#### 원가 계산 규칙 (제품 1개 기준)
```
필라멘트비 = Σ 사용량(g) × 스풀 가격 ÷ 필라멘트 스풀 무게(g)   ← 스풀 가격: 고른 색상의 가격, 없거나 색상을 안 고르면 필라멘트 가격
전기료     = 출력시간(h) × 소비전력(kW) × 전기료 단가(원/kWh)
부자재비   = Σ 수량 × 묶음 구매가 ÷ 묶음 수량
원가       = 위 세 항목 합계

수수료      = 판매가 × (주문관리 수수료% + 판매 수수료%)
순이익      = 판매가 − 원가 − 수수료 − 판매자 부담 배송비
순마진율    = 순이익 ÷ 판매가
권장 판매가 = (원가 + 배송비) ÷ (1 − 수수료율 − 목표 마진율)
```
- 가격이 미입력인 필라멘트·부자재는 0으로 계산하고 경고를 띄운다.
- 프린터 감가상각 · 출력 실패 보정은 지금은 계산하지 않는다 (추후 투자 장비 · 이윤 계산에서, 5장)

| EXP-02 | 추가/수정/삭제 | `+ 지출 추가` 또는 행을 눌러 수정. 입력: 날짜(기본 오늘, 오늘 이후 불가) · 항목 · 분류 · 금액(1원 이상) · 구매(EXP-08) · 구매처 · 메모. 삭제는 확인 한 번 (필라멘트 지출은 `재고` 스풀도 함께 지워짐, 사용한 스풀이 있으면 삭제 불가) |
| EXP-02a | 지출 복제 | 수정 창의 `복제`: 값을 복사하고 날짜는 오늘, 반복 지출 연결은 복사하지 않음. 저장해야 추가됨 |
| EXP-03 | 분류 | 고정 8개 `장비` · `필라멘트` · `부속품` · `포장재` · `소모품` · `구독 · 운영` · `판매비` · `기타` (사용자가 추가 · 수정하지 않음, 4칸 2줄 버튼 · 예시는 툴팁). 부속품 · 포장재 · 소모품은 재고 관리 탭과 같은 단위. v2 손익이 분류로 계산한다 — 아래 "분류 기준" |
| EXP-04 | 반복 지출 | `반복 지출 관리` 창: 이름 · 분류 · 금액 · 결제일(매달 N일) · 시작 달. 저절로 넣지 않고, 결제일이 지났는데 이번 달에 안 넣은 것이 있으면 알림 줄 → `확인하고 넣기` 에서 줄마다 체크 · 이번 달 금액을 고쳐 한 번에 넣는다 (날짜 = 결제일, 말일보다 크면 말일). 같은 반복 지출은 한 달에 한 번만. 그만 낼 때는 삭제(넣은 지출은 남음), 다시 내면 새로 등록 |
| EXP-05 | 요약 | 카드: 누적 투자금(`장비` 합계) · 누적 지출(전체 기간) · 이번 달 지출. 분류별 합계 막대 (기간 필터를 따름, 누르면 그 분류만) |
| EXP-06 | 검색 · 필터 | 기간(이번 달 / 올해 / 전체 / 직접 지정) · 분류 · 항목 · 구매처 · 메모 검색. 목록 위에 건수와 합계 |
| EXP-07 | CSV 내보내기 | 보이는 목록 그대로 (UTF-8 BOM): 날짜 · 항목 · 분류 · 금액 · 구매처 · 구매(구매 항목 `이름 수량단위`) · 메모 · 반복 지출 |
| EXP-08 | 구매 항목 (v2 TBD-31 · 33) | 분류가 `필라멘트` · `부속품` · `포장재` · `소모품` 이면 산 것을 항목으로 적는다 (비워도 저장 — 지출만 기록). 필라멘트 `[색상] [롤 수] [금액]`, 그 밖은 `[그 탭의 품목] [수량] [금액]`. 같은 색상 · 품목도 여러 항목 가능 (예: 화이트 9롤 + 할인 1롤). 금액을 비우면 총액(배송비 포함)에서 금액 적은 항목을 빼고 나눠 넣음 — 필라멘트는 롤 수대로, 그 밖은 비운 항목이 하나일 때만 (`여러 가지면 항목마다 금액`). 항목 아래 저장하면 바뀌는 것 (`롤당 18,000원 · 스풀 +4개 · 단가 14,400원 → 18,000원`, `재고 +200개 · 단가 60원 → 45원`, 최근 구매가 아니면 `단가 그대로`). 저장하면 (1) **필라멘트는 롤 수만큼 스풀을 바로 만든다** (상태 `재고`, 구매가 = 롤당 금액, 구매일 = 지출 날짜, 번호는 다음 번호부터) (2) 품목은 남은 수량 + 수량 (입출고 기록 `지출`, 고치면 차이만, 지우면 되돌림) (3) 그 색상 · 품목의 최근 구매면 원가 계산표 단가가 바뀜 — 색상 가격 = 롤당 금액, 품목 묶음 가격 · 수량 = 금액 · 수량 (같은 것 여러 항목이면 합계) |

- 분류가 다른 것을 한 주문에 샀으면 지출을 분류마다 한 줄씩. 영수증 파일 첨부 · 주문 링크는 없다 (구매 링크는 재고 관리 품목에)
- **최근 구매가**: 그 색상 · 품목이 들어 있는 지출 중 날짜가 가장 늦은 것 (같은 날이면 나중에 넣은 지출). 그 지출에 같은 것이 여러 항목이면 합쳐서 평균. 원가 계산표(제품 원가 · 판매 때 복사하는 원가)에만 쓰고 손익에는 쓰지 않는다. 구매 기록에서 온 단가를 손으로 고치면 다음 구매 때 덮어씀. 최근 구매 지출을 고치거나 지우면 남은 최근 구매로 돌아가고, 남은 구매가 없으면 그대로. 항목이 그대로인 수정(메모만)은 단가를 건드리지 않음
- **스풀은 지출 → 스풀 한 방향, 차이만** (TBD-33): 지출에서 롤 수를 늘리면 늘린 만큼 새 스풀, 줄이면 그 항목의 `재고` 스풀을 번호 큰 것부터 지움. 색상 · 금액 · 날짜를 바꾸면 그 항목 스풀 전부의 색상 · 구매가 · 구매일도 바뀜. 스풀에서 바꾼 것(상태 · 날짜 · 메모 · 분실 · 불량으로 지우기)은 지출에 반영하지 않음 — "차이만" 이라 스풀에서 지운 것은 지출을 고쳐도 다시 생기지 않는다. 지출로 생긴 스풀의 구매가는 지출에서만 (현금 기준 지출 합계와 손익 기준 스풀 구매가 합계가 같게)
- 사용한(사용 중 · 사용 완료) 스풀이 있는 필라멘트 항목은 색상 변경 · 빼기 · 지출 삭제를 막고, 롤 수는 `재고` 스풀이 있는 만큼만 줄일 수 있다. 못 받았거나 환불되면 지출을 지운다
- 할부 · 여러 개 묶음 구매도 결제 금액 그대로 한 줄 (실제로 빠져나간 날 기준)

| 필라멘트 | 필라멘트 스풀 | 넣지 않음. 사용 시작한 스풀 구매가로 대신 |

| 포장재 | 박스 · OPP 봉투 · 완충재 | 재료비 (산 날) |
| 소모품 | 접착제 · 노즐 · 베드 시트 · 윤활유 | 운영비 |
| 구독 · 운영 | AI 구독 · 플랫폼 월정액 · 전기요금 | 운영비 |
| 판매비 | 택배비 · 포장 외 발송비 · 광고비 | 운영비 |
| 기타 | 위에 안 맞는 것 | 운영비 |

- 분류를 고정하는 이유: v2 손익이 이 분류를 그대로 쓴다. 장비 · 필라멘트처럼 손익 기준에서 다르게 다루는 것을 처음부터 나눠 두어야 나중에 다시 분류하지 않는다

### 3.9 시스템 — `SYS`
| ID | 기능 | 상세 |
|---|---|---|
| SYS-02 | 로컬 네트워크 접속 | 같은 와이파이에서 `http://PC내부IP:5173` (개발 서버). QR 라벨 안의 주소 앞부분은 `backend/.env` 의 `PUBLIC_URL` — 비우면 PC 에서 연 주소를 써서 `localhost` 면 폰에서 안 열림(화면에 경고). 공유기에서 PC 주소 고정(DHCP 예약) 권장 — 바뀌면 붙인 라벨이 안 열림 |
| SYS-03 | 관리자 화면 | Django 관리자(`/admin`)에서 모든 데이터 조회·수정 |
| SYS-05 | 화면 이동 | 왼쪽 사이드바 메뉴 (제품 원가 · 필라멘트 · 부자재 · 판매 · 지출, 맨 아래 `설정`). 앱을 열면 제품 원가. 접으면 아이콘만, 펼치면 이름까지. 접힘 상태는 기억 |
| SYS-06 | 테마 | 사이드바에서 시스템 / 라이트 / 다크 선택 (기본 시스템). 고른 값은 기억 |
| SYS-04 | 실행 | 개발 중에는 백엔드(Django)와 프론트(Vite) 개발 서버를 각각 실행. 사용할 때는 React 빌드 결과를 Django 가 함께 제공해 서버 하나로 실행 |
