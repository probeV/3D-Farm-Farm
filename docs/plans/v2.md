> 요구사항: [PRD.md](../PRD.md) · 화면: [screens.md](../screens.md) · 아이디어 보관함: [TBD.md](../TBD.md) · 이전: v1.2.0 (지출 장부, 완료)

이번 버전에서 할 일. **판매 장부 · 손익 계산 · 스마트스토어 연동** — v1.2.0 지출 장부에 번 돈을 더해 손익분기점과 순이익을 본다.
개발이 끝나면 [PRD.md](../PRD.md) · [screens.md](../screens.md) · [ERD.md](../ERD.md) 에 반영하고 이 파일은 지운다. 못 끝낸 항목은 다음 버전 계획이나 [TBD.md](../TBD.md) 로 옮긴다.
범위가 커서, 판매가 늘기 전에 필요해지면 판매 장부(`SALE`)만 v1.3 으로 먼저 떼어 낼 수 있다.

## 돈을 보는 두 관점

손익 화면 하나에서 위쪽 `현금 기준` / `손익 기준` 으로 바꿔 본다. 두 관점은 필라멘트 · 장비를 가져오는 곳이 달라 서로 겹치지 않는다.

| 항목 | 현금 기준 (통장) | 손익 기준 (쓴 만큼) |
|---|---|---|
| 매출 | 판매 장부 | 판매 장부 |
| 필라멘트 | 지출 장부 — **산 날** | **사용 시작한 스풀**의 구매가 (사용 시작일 기준). 구매가가 없으면 색상 가격 → 필라멘트 가격 |
| 부자재 | 지출 장부 — 산 날 | 지출 장부 — 산 날 (현금 기준과 같음) |
| 운영비 (소모품 · 구독 · 판매비 · 기타) | 지출 장부 | 지출 장부 |
| 장비 (`투자(장비)`) | 지출 장부 — 산 날 | 넣지 않음 → 투자 회수(PL-02)로 따로 |
| 함께 보는 것 | 누적 잔액 · 투자 회수 · 손익분기점 | 월 이익 |

- **제품 원가는 손익에 쓰지 않는다.** 제품 원가는 제품 정리 · 판매가 정하기용이고, 손익은 실제 기록(판매 · 지출 · 스풀)으로만 계산한다
- 스풀 방식이라 실패 출력 · 테스트 출력 · 자투리도 따로 계산하지 않아도 손익에 들어간다
- **감가상각은 하지 않는다.** 장비값은 손익에서 빼고 회수율로 본다 (회사의 EBITDA · 회수 기간과 같은 방식). 세금 신고용 감가상각은 세무 쪽에서
- 부자재는 아직 금액이 작아 손익 기준도 산 날로 본다. 관리할 필요가 생기면 스풀처럼 묶음을 뜯은 날(사용 시작) 기준으로 바꾼다

## 기능

### 판매 장부 — `SALE`

> 목업: [mockups/sales.html](../mockups/sales.html)

| ID | 기능 | 내용 |
|---|---|---|
| SALE-01 | 판매 목록 | 주문 한 줄: 날짜 · 판매처 · 제품(여러 개면 "외 N") · 수량 · 판매가 · 받은 배송비 · 수수료 · 정산 금액 · 원가 · 이익 · 메모. 기간 · 판매처 · 검색, 열 제목 정렬, CSV. 요약 카드(이번 달 매출 · 정산 금액 · 주문 이익 · 누적 매출), 제품별 판매(누르면 그 제품 주문만) |
| SALE-02 | 판매 추가 / 수정 / 복제 / 삭제 | 판매처는 `스마트스토어` · `직접 판매` · `기타` 고정. 제품은 등록된 제품에서 고르고 단가는 제품 판매가가 기본값(고칠 수 있음). 받은 배송비 · 주문번호 · 메모 |
| SALE-03 | 수수료 · 정산 금액 | 스마트스토어면 수수료 = (판매가 합계 + 받은 배송비) × (SET-06 + SET-07) 자동, 직접 고치면 그 값으로 고정 · `다시 계산`. 정산 금액 = 판매가 + 받은 배송비 − 수수료 |
| SALE-04 | 한 주문에 여러 제품 | 주문 하나에 제품 여러 줄 (배송비 · 수수료는 주문 단위) |
| SALE-05 | 주문별 이익 (참고) | 판매를 저장할 때 원가 계산표의 개당 원가를 복사해 둔다(나중에 가격이 바뀌어도 지난 판매는 그대로, 판매 창에서는 보기만). 이익 = 정산 금액 − 원가 − 낸 택배비(기본 SET-08). **손익(PL)에는 쓰지 않는다** |

- 판매자가 낸 택배비는 손익 계산에는 지출 장부(판매비)의 것을 쓴다. 주문의 `낸 택배비` 는 주문별 이익 참고용
- 원가 계산표에 원가가 없는 제품(입력이 덜 됨)은 `원가 없음` — 그 주문의 이익은 비움

### 손익 — `PL`

> 목업: [mockups/pl.html](../mockups/pl.html)

| ID | 기능 | 내용 |
|---|---|---|
| PL-01 | 손익 (월 · 연 · 전체) | `현금 기준` / `손익 기준` 전환 (위 "돈을 보는 두 관점"). 아래 계산 순서. 기간은 달력처럼 고른다 — 연도 넘기기 + 1~12월 칸(기록 없는 달은 흐리게) + `○년` · `전체 기간`, 양옆 ‹ › 로 한 칸씩 |
| PL-02 | 투자 회수 | 누적 투자금(`투자(장비)` 합계) · 누적 순이익(손익 기준) · **회수율** (누적 순이익 ÷ 누적 투자금) 막대. 기간과 상관없이 전체로 |
| PL-04 | 월별 그래프 | 손익 기준: 매출 · 비용 막대 + 순이익 점 / 현금 기준: 들어온 · 나간 돈 막대 + 누적 잔액 선. 막대를 누르면 그 달로 |
| PL-05 | 두 기준 차이 | 같은 기간 현금 기준 남은 돈과 손익 기준 순이익이 왜 다른지 — 장비 구매 · (필라멘트 산 돈 − 뜯은 스풀) |
| PL-06 | 세금 | 종합소득세 등 낸 세금을 지출로 기록해 순이익에서 뺀다. 지출 분류(EXP-03)에 `세금` 추가 (목업에는 `기록 없음` 자리만) |

- PL-03 손익분기점("앞으로 N개 더 팔면 회수")은 목업 검수에서 뺐다. 투자 회수 카드의 `남은 금액` 도 뺌

#### 계산 순서

손익 기준:
```
매출액                 판매 장부의 판매가 합계 + 받은 배송비 (택배비 지출과 맞추려고)
− 재료비               사용 시작한 스풀 구매가 + 부자재 지출
= 매출총이익
− 운영비               판매 수수료(판매 장부) + 지출의 판매비 · 구독 · 소모품 · 기타 (장비 제외)
= 영업이익
± 영업외 손익           이자 수입 · 이자 비용 등
− 세금                 종합소득세 등
= 순이익
```

현금 기준: `들어온 돈(판매 정산 금액) − 나간 돈(지출 장부 전부, 장비 포함)` 월별 + 누적 잔액

#### 구현 방식

- **새로 저장하는 것 없음.** 손익 화면은 기간을 고르면 아래 세 기록을 분류 조건으로 더하기만 한다. 지출 장부의 **분류(EXP-03)** 가 핵심

| 기록 | 입력하는 곳 | 손익에서 쓰는 값 |
|---|---|---|
| `Expense` (지출) | 지출 장부 (v1.2.0) | 날짜 · 분류 · 금액 |
| `Sale` (판매) | 판매 장부 | 날짜 · 판매가 · 수수료 · 정산 금액 |
| `Spool` (스풀, 이미 있음) | 필라멘트 화면 | 구매가 · 사용 시작일(`opened_at`) |

```
현금 기준 (기간)   = Sale 정산 금액 합계 − Expense 합계 (모든 분류)
손익 기준 (기간)   = Sale 판매가 + 받은 배송비 합계 − 수수료 합계
                   − 그 기간에 사용 시작한 Spool 구매가 합계 (없으면 색상 → 필라멘트 가격)
                   − Expense 합계 (분류가 `투자(장비)` · `필라멘트` 가 아닌 것)
투자 회수 (PL-02)  = 처음부터 지금까지 손익 기준 이익 합계 ÷ `투자(장비)` 지출 합계
```

- "장비를 손익에서 뺀다" = 손익 기준을 더할 때 `투자(장비)` 분류를 조건으로 빼는 것. 장비값은 현금 기준(산 달에 그대로)과 투자 회수(회수율)에서 보인다
  - 예: 1월 프린터 120만 원, 매달 매출 50만 · 재료비 + 운영비 30만 → 손익 기준 월 이익은 매달 20만, 투자 회수는 1월 17% → 2월 33% → 3월 50%
- **부가세는 비용이 아니다**: 손님에게 받아 대신 내는 돈이라 손익에서 뺀다. 간이과세자면 처리가 달라 사업자 유형에 맞춘다

### 스마트스토어 연동 — `STORE`

| ID | 기능 | 내용 |
|---|---|---|
| STORE-01 | 정산 엑셀 올리기 | API 가 안 될 때 예비. 판매자센터에서 받은 엑셀을 올리면 STORE-03 과 같은 미리보기로 |
| STORE-02 | 상품 연결 | 스토어 상품(옵션)마다 이 앱의 제품을 한 번 짝지어 두고, 다음부터 자동으로. 미리보기에서 바로 고를 수도 있음. `스토어 상품 다시 불러오기` |
| STORE-03 | 커머스 API 로 가져오기 | **메인 방식** (내스토어 애플리케이션 발급 완료). 주문일 기간(기본: 마지막으로 가져온 날 ~ 오늘) → 미리보기 → 확인한 주문만 판매 장부에 |
| STORE-04 | 연결 상태 | 애플리케이션 ID · 시크릿은 `backend/.env` (`NAVER_COMMERCE_CLIENT_ID` · `NAVER_COMMERCE_CLIENT_SECRET`) 에서 읽는다. 화면은 `연결됨` · `연결 안 됨(.env 에 값 없음)` · `연결 실패` 와 `연결 확인` 만 — 화면 · DB · 백업에 시크릿을 저장하지 않음 |
| STORE-05 | 가져오기 기록 | 언제 · 어느 기간 · 몇 건 넣음 · 몇 건 뺌 |

> 목업: [mockups/store.html](../mockups/store.html) — `판매 › 스마트스토어 연동` (판매 화면의 `스마트스토어 가져오기` 버튼)

- 스마트스토어는 매출 · 수수료까지만 준다. 원가 · 다른 비용 · 손익은 이 앱에서 계산한다
- 미리보기: 주문번호 하나에 상품주문 여러 줄 → 판매 한 건(SALE-04). 수수료 · 정산 금액은 API 의 실제 값. 같은 주문번호가 이미 있으면 `이미 있음`, 취소는 `취소`, 연결 안 된 상품이 있으면 `상품 연결 필요` — 셋 다 넣지 않음
- 정산 전 주문은 `예정` 금액으로 넣고, 다음 가져오기 때 정산 완료 값으로 맞춘다 (안)
- 정할 것: 정산 전 주문도 넣을지 / 구매확정만 · 이미 넣은 주문이 나중에 취소 · 반품되면 판매 장부에서 어떻게 할지 · 호출 IP 등록이 필요한지 (커머스API센터 확인)

  - 발급: "라벨 N장" → 다음 번호부터 N개 예약(예: S00101~S00150, 시작 번호 지정 가능). 스풀 행은 만들지 않고 번호 범위만 기록(`LabelBatch`). 같은 묶음 다시 인쇄, 발급 안 한 번호를 찍으면 거부
  - 출력: QR + 코드 라벨 (예: 40×30mm)
  - 등록: 회사 → 필라멘트 → 색상 · 구매가 · 구매일을 한 번 정해 두고 같은 색 스풀을 연속으로 찍기. 결과는 목록에 쌓이고 줄마다 취소, 이미 등록된 코드는 "이미 등록됨"
  - 모드: `등록` · `사용 시작` · `사용 완료` · `조회` 중 골라서 찍기 (자동으로 다음 상태로 넘기지 않음 — 실수 방지)
  - 라벨 없이 등록: 지금의 재고 추가 그대로 (라벨과 같은 번호 순서)
- **정함** (목업 [mockups/qr.html](../mockups/qr.html) — `필라멘트 › QR 스풀 관리`):
  - 라벨 출력 — **라벨 프린터** (40×30 · 50×30mm, 예비로 A4 라벨지 24칸). 브라우저 인쇄 창에서 프린터를 고름
  - 찍는 도구 — **폰 기본 카메라**. QR 안에는 **주소** `{PUBLIC_URL}/s/{코드}` (`PUBLIC_URL` 은 `backend/.env`). 폰과 PC 가 같은 와이파이, `DJANGO_ALLOWED_HOSTS` 에 PC IP, 공유기에서 PC 주소 고정(DHCP 예약) 권장 — 주소가 바뀌면 붙인 라벨이 안 열림
  - 번호 예약 · 발급 기록(`LabelBatch`) **없음**. `마지막으로 인쇄한 번호` 하나만 기억하고 `새 라벨` 은 항상 다음 번호부터. 인쇄 기록은 버튼 → 창
  - 화면 위치 — **필라멘트 화면 안 `QR` 버튼** (사이드바는 그대로)
  - `다시 인쇄` — 등록된 스풀(라벨에 색상 · 필라멘트도 찍힘)과 인쇄했지만 등록 안 된 번호를 골라서. 번호는 그대로
  - 등록 안 된 번호는 비어 있어도 괜찮음 (건너뛰거나 같은 번호로 다시 인쇄, 나중에 찾은 라벨도 정상 등록). 인쇄한 적 없는 번호만 폰에서 거부
  - 폰 화면 (찍으면 열림, 앱 설치 없음): 새 라벨 → `지난번과 같게` 한 번 누르기 또는 필라멘트 · 색상 · 구매가 · 구매일 / 재고 → `사용 시작` / 사용 중 → `사용 완료` (+ 되돌리기) / 사용 완료 → 조회만. 상태는 버튼을 눌러야 바뀜 (모드 고르기 대신)
  - 라벨 없이 등록 — 지금의 재고 추가 그대로 (같은 번호 순서)
- **반영할 곳**: PRD 3.4 · 3.5 · 5장 · ERD(마지막으로 인쇄한 번호 · 인쇄 기록) · api.md · screens.md 1장 · 목업 · 서버(`services.py` 로 스캔 동작 공통화, architecture.md 2장) · 화면

### TBD-31 스풀 · 부자재 구매를 지출과 잇기 (v1.2.0 에서 남김)

- **지금**: 지출 장부(PRD 3.10)와 스풀 재고 추가(INV-02) · 부자재 구매가를 따로 입력한다. 같은 구매를 두 번 적게 된다.
  v1.2.0 에서는 지출은 주문 단위(배송비 포함 · 여러 색 한 번에), 스풀은 한 통 단위라 맞지 않아 잇지 않았다.
- **정함** (목업 [mockups/expenses.html](../mockups/expenses.html) · [qr.html](../mockups/qr.html) · [filaments.html](../mockups/filaments.html) · [parts.html](../mockups/parts.html)):
  - 입력 방향 — **지출에 주문 한 줄**, 스풀은 그 주문에 **연결**. 지출 분류가 `필라멘트` · `부자재` 면 `산 것` 줄을 적는다
    - 필라멘트: `[색상] [통 수] [금액]`. 금액을 비우면 총액(배송비 포함)을 통 수대로 나눔 → 통당 구매가
    - 부자재: `[부자재] [수량] [금액]`. 한 줄이면 총액, 여러 가지면 줄마다 금액
    - 필라멘트와 부자재를 한 주문에 샀으면 지출을 두 줄로 (분류가 하나라서)
  - 배송비 — 스풀 구매가에 **나눠 넣음** (실제 낸 돈이 손익 기준 재료비에 그대로)
  - 스풀 등록 — 폰 QR 등록 · 재고 추가에서 **주문(지출 장부)을 고르면** 구매가 · 구매일이 주문에서 들어옴(고칠 수 없음, 수량은 남은 통까지). 그 색상이 남은 최근 주문이 기본값, `주문 없이` 면 직접 입력. 지출 목록에 `🧵 6통 · 등록 3`
  - 원가 계산표 단가 — **최근 구매가**. 지출을 저장할 때 그 색상 · 부자재의 최근 구매면 색상 가격 · 부자재 묶음 가격이 바뀐다 (가격 옆에 `최근 구매가 · 날짜 주문명 (지출)`). 산 적 없는 것은 지금처럼 직접 입력
    - 원가 계산표(제품 원가 화면 · 판매 때 복사하는 원가)에만 쓰고 **손익에는 안 씀** — 손익은 스풀 각각의 구매가와 부자재 지출 그대로. 남은 재고보다 비싸게 다시 샀을 때 원가가 잠시 높게 보이는 건 감수 (판매가를 정하기엔 안전한 쪽)
  - 남은 것 — 구매 기록에서 온 단가를 손으로 고치면 다음 구매 때 덮어씀 · 지출을 나중에 고치거나 지우면 이미 등록한 스풀 구매가는 그대로 (개발 때 다시 확인)
