# v2 계획 — 3D Farm Farm (쓰리디팜팜)

> 요구사항: [PRD.md](../PRD.md) · 화면: [screens.md](../screens.md) · 아이디어 보관함: [TBD.md](../TBD.md) · 이전: v1.2.0 (지출 장부, 완료)

이번 버전에서 할 일. **판매 장부 · 손익 계산 · 스마트스토어 연동** — v1.2.0 지출 장부에 번 돈을 더해 손익분기점과 순이익을 본다.
함께 **재고 관리**(필라멘트 · 부속품 · 포장 · 소모품)로 부자재를 나누고 남은 수량을 센다 (아래 `STOCK`).
개발이 끝나면 [PRD.md](../PRD.md) · [screens.md](../screens.md) · [ERD.md](../ERD.md) 에 반영하고 이 파일은 지운다. 못 끝낸 항목은 다음 버전 계획이나 [TBD.md](../TBD.md) 로 옮긴다.
범위가 커서, 판매가 늘기 전에 필요해지면 판매 장부(`SALE`)만 v1.3 으로 먼저 떼어 낼 수 있다.

## 돈을 보는 두 관점

손익 화면 하나에서 위쪽 `현금 기준` / `손익 기준` 으로 바꿔 본다. 두 관점은 필라멘트 · 장비를 가져오는 곳이 달라 서로 겹치지 않는다.

| 항목 | 현금 기준 (통장) | 손익 기준 (쓴 만큼) |
|---|---|---|
| 매출 | 판매 장부 | 판매 장부 |
| 필라멘트 | 지출 장부 — **산 날** | **사용 시작한 스풀**의 구매가 (사용 시작일 기준). 구매가가 없으면 색상 가격 → 필라멘트 가격 |
| 부속품 · 포장재 | 지출 장부 — 산 날 | 지출 장부 — 산 날 (현금 기준과 같음) |
| 운영비 (소모품 · 구독 · 운영 · 판매비 · 기타) | 지출 장부 | 지출 장부 |
| 장비 (`장비`) | 지출 장부 — 산 날 | 넣지 않음 → 투자 회수(PL-02)로 따로 |
| 함께 보는 것 | 누적 잔액 · 투자 회수 · 손익분기점 | 월 이익 |

- **제품 원가는 손익에 쓰지 않는다.** 제품 원가는 제품 정리 · 판매가 정하기용이고, 손익은 실제 기록(판매 · 지출 · 스풀)으로만 계산한다
- 스풀 방식이라 실패 출력 · 테스트 출력 · 자투리도 따로 계산하지 않아도 손익에 들어간다
- **감가상각은 하지 않는다.** 장비값은 손익에서 빼고 회수율로 본다 (회사의 EBITDA · 회수 기간과 같은 방식). 세금 신고용 감가상각은 세무 쪽에서
- 부속품 · 포장재는 아직 금액이 작아 손익 기준도 산 날로 본다 (남은 수량은 재고 관리에서 세지만 손익은 지출 그대로). 관리할 필요가 생기면 판매로 빠진 만큼(쓴 만큼) 기준으로 바꾼다

## 기능

### 판매 장부 — `SALE`

> 목업: [mockups/sales.html](../mockups/sales.html)

| ID | 기능 | 내용 |
|---|---|---|
| SALE-01 | 판매 목록 | 주문 한 줄: 날짜 · 판매처 · 제품(여러 개면 "외 N") · 수량 · 판매가 · 받은 배송비 · 수수료 · 정산 금액 · 원가 · 이익 · 메모. 기간 · 판매처 · 검색, 열 제목 정렬, CSV. 요약 카드(이번 달 매출 · 정산 금액 · 주문 이익 · 누적 매출), 제품별 판매(누르면 그 제품 주문만) |
| SALE-02 | 판매 추가 / 수정 / 복제 / 삭제 | 판매처는 `스마트스토어` · `직접 판매` · `기타` 고정. 제품은 등록된 제품에서 고르고 단가는 제품 판매가가 기본값(고칠 수 있음). 받은 배송비 · 주문번호 · 메모 |
| SALE-03 | 수수료 · 정산 금액 | 스마트스토어면 수수료 = (판매가 합계 + 받은 배송비) × (SET-06 + SET-07) 자동, 직접 고치면 그 값으로 고정 · `다시 계산`. 정산 금액 = 판매가 + 받은 배송비 − 수수료 |
| SALE-04 | 한 주문에 여러 제품 | 주문 하나에 제품 여러 줄 (배송비 · 수수료는 주문 단위) |
| SALE-05 | 주문별 이익 (참고) | 판매를 저장할 때 원가 계산표의 개당 원가(**포장 빼고**)를 복사해 둔다(나중에 가격이 바뀌어도 지난 판매는 그대로, 판매 창에서는 보기만). 이익 = 정산 금액 − 제품 원가 − 포장비(SALE-06) − 낸 택배비(기본 SET-08). **손익(PL)에는 쓰지 않는다** |
| SALE-06 | 주문 포장 | 주문 단위 포장 줄 `포장재 · 수량 · 금액` (제품 줄과 따로, 묶음 포장 대응). 새 주문은 첫 제품의 기본 포장(STOCK-06) 구성으로 채움 · `+ 포장 세트 더하기` 는 세트 구성을 지금 줄에 더함(같은 포장재는 수량 합침) · `+ 포장재 추가` · 줄마다 바꾸기 · ✕. 직접 전달이면 비움(`포장 없음`). 남은 수량보다 많으면 수량과 금액 사이 주황 `!` (툴팁 `0회 남음`), 저장은 막지 않음. 단가도 저장 때 복사. 목록 `원가` 칸 = 제품 원가 + 포장비 |

- 판매자가 낸 택배비는 손익 계산에는 지출 장부(판매비)의 것을 쓴다. 주문의 `낸 택배비` 는 주문별 이익 참고용
- 원가 계산표에 원가가 없는 제품(입력이 덜 됨)은 `원가 없음` — 그 주문의 이익은 비움
- 판매를 저장하면 부속품(제품 × 수량)과 포장재(포장 줄)가 남은 수량에서 빠진다 (STOCK-04). 고치면 차이만, 지우면 되돌림

### 손익 — `PL`

> 목업: [mockups/pl.html](../mockups/pl.html)

| ID | 기능 | 내용 |
|---|---|---|
| PL-01 | 손익 (월 · 연 · 전체) | `현금 기준` / `손익 기준` 전환 (위 "돈을 보는 두 관점"). 아래 계산 순서. 기간은 달력처럼 고른다 — 연도 넘기기 + 1~12월 칸(기록 없는 달은 흐리게) + `○년` · `전체 기간`, 양옆 ‹ › 로 한 칸씩 |
| PL-02 | 투자 회수 | 누적 투자금(`장비` 합계) · 누적 순이익(손익 기준) · **회수율** (누적 순이익 ÷ 누적 투자금) 막대. 기간과 상관없이 전체로 |
| PL-04 | 월별 그래프 | 손익 기준: 매출 · 비용 막대 + 순이익 점 / 현금 기준: 들어온 · 나간 돈 막대 + 누적 잔액 선. 막대를 누르면 그 달로 |
| PL-05 | 두 기준 차이 | 같은 기간 현금 기준 남은 돈과 손익 기준 순이익이 왜 다른지 — 장비 구매 · (필라멘트 산 돈 − 뜯은 스풀) |
| PL-06 | 세금 | 종합소득세 등 낸 세금을 지출로 기록해 순이익에서 뺀다. 지출 분류(EXP-03)에 `세금` 추가 (목업에는 `기록 없음` 자리만 · 지출 목업의 분류 8개에는 아직 없음) |

- PL-03 손익분기점("앞으로 N개 더 팔면 회수")은 목업 검수에서 뺐다. 투자 회수 카드의 `남은 금액` 도 뺌

#### 계산 순서

손익 기준:
```
매출액                 판매 장부의 판매가 합계 + 받은 배송비 (택배비 지출과 맞추려고)
− 재료비               사용 시작한 스풀 구매가 + 부속품 · 포장재 지출
= 매출총이익
− 운영비               판매 수수료(판매 장부) + 지출의 판매비 · 구독 · 운영 · 소모품 · 기타 (장비 제외)
= 영업이익
± 영업외 손익           이자 수입 · 이자 비용 등
− 세금                 종합소득세 등
= 순이익
```

현금 기준: `들어온 돈(판매 정산 금액) − 나간 돈(지출 장부 전부, 장비 포함)` 월별 + 누적 잔액

#### 구현 방식

- **새로 저장하는 것 없음.** 손익 화면은 기간을 고르면 아래 세 기록을 분류 조건으로 더하기만 한다. 지출 장부의 **분류(EXP-03)** 가 핵심

| 기록 | 입력하는 곳 | 손익에서 쓰는 값 |
|---|---|---|
| `Expense` (지출) | 지출 장부 (v1.2.0) | 날짜 · 분류 · 금액 |
| `Sale` (판매) | 판매 장부 | 날짜 · 판매가 · 수수료 · 정산 금액 |
| `Spool` (스풀, 이미 있음) | 필라멘트 화면 | 구매가 · 사용 시작일(`opened_at`) |

```
현금 기준 (기간)   = Sale 정산 금액 합계 − Expense 합계 (모든 분류)
손익 기준 (기간)   = Sale 판매가 + 받은 배송비 합계 − 수수료 합계
                   − 그 기간에 사용 시작한 Spool 구매가 합계 (없으면 색상 → 필라멘트 가격)
                   − Expense 합계 (분류가 `장비` · `필라멘트` 가 아닌 것)
투자 회수 (PL-02)  = 처음부터 지금까지 손익 기준 이익 합계 ÷ `장비` 지출 합계
```

- "장비를 손익에서 뺀다" = 손익 기준을 더할 때 `장비` 분류를 조건으로 빼는 것. 장비값은 현금 기준(산 달에 그대로)과 투자 회수(회수율)에서 보인다
  - 예: 1월 프린터 120만 원, 매달 매출 50만 · 재료비 + 운영비 30만 → 손익 기준 월 이익은 매달 20만, 투자 회수는 1월 17% → 2월 33% → 3월 50%
- **부가세는 비용이 아니다**: 손님에게 받아 대신 내는 돈이라 손익에서 뺀다. 간이과세자면 처리가 달라 사업자 유형에 맞춘다

### 재고 관리 — `STOCK`

> 목업: [mockups/filaments.html](../mockups/filaments.html) · [parts.html](../mockups/parts.html) · [packaging.html](../mockups/packaging.html) · [consumables.html](../mockups/consumables.html) (+ 제품 원가 · 판매 · 지출 · 손익 목업 연동)

부자재 하나로 묶여 있던 것을 **원가에 들어가는 방식**대로 나누고, 남은 수량을 센다. 탭(고정)은 동작이 다른 것, 탭 안 카테고리(직접 추가)는 물건 종류.

| 탭 | 무엇 | 원가에 들어가는 곳 | 남은 수량이 느는 때 | 주는 때 |
|---|---|---|---|---|
| 필라멘트 | 지금 그대로 (회사 › 필라멘트 › 색상 › 스풀, QR) | 제품 1개당 g | 스풀 등록 | 스풀 사용 시작 · 완료 |
| 부속품 | 제품에 붙는 것 (자석 · 볼트 · LED · 키링 고리) | 제품 1개당 수량 | 지출 `부속품` 구매 | 판매 (제품 × 수량) |
| 포장 | 포장재(박스 · 봉투 · 완충재 · 스티커 · 테이프) + 포장 세트 | 제품의 기본 포장(권장 판매가) · 판매 주문의 포장 줄 | 지출 `포장재` 구매 | 판매 (주문의 포장 줄) |
| 소모품 | 여러 제품에 조금씩 써서 셀 수 없는 것 (접착제 · 사포 · 노즐 · 베드 시트 · IPA) | **넣지 않음** — 지출 `소모품` 으로 손익 운영비 | 지출 `소모품` 구매 | `1개 다 씀` 버튼 |

| ID | 기능 | 내용 |
|---|---|---|
| STOCK-01 | 재고 관리 화면 | 사이드바 `필라멘트` · `부자재` 대신 `재고 관리` 하나 (누르면 필라멘트 탭). 화면 위 탭 `필라멘트 \| 부속품 \| 포장 \| 소모품`. QR 은 필라멘트 탭 안 그대로 |
| STOCK-02 | 카드 보기 | 부속품 · 포장재 · 소모품 목록은 **카테고리별 묶음**: 묶음 맨 위 제목 띠(옅은 바탕 · 왼쪽 파란 막대 · 큰 이름 · `N개` · 주황 `부족 · 없음 N` 알약) + 사진 타일. 타일은 폭에 맞춰 늘어남(최소 168px, 1440px 에서 한 줄 6개). 타일: 사진(없으면 첫 글자 + `사진 없음`) · 부족/없음 배지 · 구매 링크 · 이름(2줄) · 구매처 · 사용 제품 수 / 세트 수 · 남은 수량(크게) · 개당 단가. 묶음 끝 `+ 추가` 타일. `카드 \| 표` 전환(표에도 남은 수량) |
| STOCK-03 | 사진 | 부속품 · 포장재 · 소모품에 사진 1장 (넣기 · 바꾸기 · 빼기). 제품 사진과 같은 방식으로 파일 저장 |
| STOCK-04 | 남은 수량 | 품목마다 남은 수량 · 부족 알림 기준. 기준 이하 `부족`(주황) · 0 이하 `없음`(빨강). 요약 카드 `부족 · 없음` (누르면 그 품목만). 지출 구매로 늘고, 판매 저장으로 줄고(부속품 · 포장재), 그 밖은 `조정` 창 — `실제 수량으로 맞추기 / 빼기 / 더하기` + 사유. 처음 등록할 때 지금 수량 입력 |
| STOCK-05 | 입출고 기록 | 품목 창 아래 최근 순: 날짜 · 지출 / 판매 / 다 씀 / 조정 · ± 수량 · 그 뒤 남은 수량 |
| STOCK-06 | 포장 세트 · 기본 포장 | 포장재 조합에 이름 (예: 봉투 포장 · 작은 박스 · 큰 박스(묶음)). 세트 카드: 구성 · 세트 원가 · 기본 포장인 제품 수 · 바로 쌀 수 있는 수(가장 모자란 포장재 기준). 제품 창에 `기본 포장`(1개 보낼 때) 세트 하나 → 제품 원가 · 권장 판매가에 `포장비` 로 들어감, 안 고르면 `입력 필요`. 쓰는 제품이 있으면 세트 삭제 불가 |
| STOCK-07 | 소모품 | 원가에 넣지 않음. 타일 · 표에 `1개 다 씀` 버튼(남은 수량 −1, 부족이면 알림) · 마지막으로 다 쓴 날. 최근 구매가는 참고용. 요약 카드에 이번 달 지출 `소모품` 합계 |

### TBD-18 QR 스풀 관리 (등록된 스풀의 라벨 인쇄 · 찍어서 상태 바꾸기) — ✅ 완료

> 서버 · 화면 완료 · PRD INV-09 · 10 · 11 · UNDO-02 · 03 · SYS-02 · 5장 · ERD · api.md · architecture.md · screens.md 1.1 · 1.7 · 1.10 · 1.11 · 5.3 반영.

> 화면 `QR` 버튼 → 라벨 인쇄(QR 은 `qrcode-generator`, 브라우저 인쇄 창) · 폰 스풀 화면 `/s/{코드}` · 지출 저장 · 재고 추가 알림의 `라벨 인쇄`.
> 개발 때 정한 것: 인쇄 창을 닫으면 `라벨 뽑음`(인쇄했는지 브라우저가 알려 주지 않아서 — 취소했으면 알림의 되돌리기) ·
> `PUBLIC_URL` 이 없으면 PC 에서 연 주소를 쓰고 `localhost` 면 주황 경고 · `PUBLIC_URL` 포트는 화면(Vite) 5173 (Django 8000 아님 — Vite 가 /api 를 넘겨줘서 `DJANGO_ALLOWED_HOSTS` 에 PC IP 는 필요 없음) ·
> 라벨 크기는 브라우저에 기억 · 지출의 `라벨 인쇄` 는 그 지출 스풀 중 라벨 없는 것 · 폰에서 사용 완료를 되돌리면 `사용 중으로 되돌렸어요`

- **지금**: 스풀 코드(`S00001`)는 DB id 와 따로 `code_no` 로 저장해 라벨용으로 대비해 두었고, 코드로 스풀 찾기(INV-09)가 있다. QR 라벨 · 스캔 기능은 없다.
- **불편**: 스풀을 사용 시작 · 완료할 때 PC 에서 색상을 찾고 스풀 코드를 골라야 한다
- **정함** (2026-11-13 다시 정함 — TBD-33 으로 스풀이 지출 저장 때 생기므로):
  ```
  스풀 등록 (필라멘트 지출 저장 · 재고 추가) → 코드가 이미 붙어 있음 → 그 스풀의 라벨 인쇄 → 붙이기 → 폰으로 찍어 상태 바꾸기
  ```
  - **라벨은 이미 등록된 스풀로만 인쇄** — 번호만 미리 뽑는 `새 라벨` · 번호 예약 · `마지막으로 인쇄한 번호` · 폰에서 `등록` 은 없음
    - 인쇄할 스풀 고르기: 방금 등록한 스풀(지출 저장 · 재고 추가 뒤 `라벨 인쇄` 바로가기) · 라벨을 아직 안 뽑은 스풀 · 다시 인쇄할 스풀
    - 라벨: QR + 코드 + 필라멘트 · 색상 이름 (같은 색 스풀은 아무 라벨이나 붙여도 됨)
  - **폰은 상태 바꾸기 전용** — 찍으면 그 스풀 화면이 열림 (앱 설치 없음): 재고 → `사용 시작` / 사용 중 → `사용 완료` (+ 되돌리기) / 사용 완료 → 조회만. 상태는 버튼을 눌러야 바뀜
  - 그대로인 것 (목업 [mockups/qr.html](../mockups/qr.html)):
    - 라벨 출력 — **라벨 프린터** (40×30 · 50×30mm, 예비로 A4 라벨지 24칸). 브라우저 인쇄 창에서 프린터를 고름
    - 찍는 도구 — **폰 기본 카메라**. QR 안에는 **주소** `{PUBLIC_URL}/s/{코드}` (`PUBLIC_URL` 은 `backend/.env`). 폰과 PC 가 같은 와이파이, `DJANGO_ALLOWED_HOSTS` 에 PC IP, 공유기에서 PC 주소 고정(DHCP 예약) 권장 — 주소가 바뀌면 붙인 라벨이 안 열림
    - 화면 위치 — **필라멘트 화면 안 `QR` 버튼** (사이드바는 그대로)
  - 지운 스풀 번호는 다시 쓰지 않음 (TBD-33) — 라벨을 붙였다가 지운 스풀의 번호가 다른 스풀에 붙지 않게.
    지금까지 쓴 가장 큰 번호를 따로 기억해 다음 번호 = 그 번호 + 1. 재고 추가의 `번호 지정`(지운 번호 다시 쓰기)은 **삭제** — 번호는 항상 자동
  - 라벨을 뽑았는지 **스풀마다 기억** — PC 인쇄 목록은 `라벨 없음 N`(기본) · `전체 · 다시 인쇄` 탭, 맨 위 전체 선택 체크박스. 인쇄하면 `라벨 없음` 에서 빠짐
  - 지출 저장 · 재고 추가 알림 오른쪽 `라벨 인쇄` → QR 화면이 그 스풀을 골라 둔 채로 열림 (`방금 저장한 지출 … 의 스풀 · N개 골라 뒀어요`)
  - 폰: 지운 스풀의 라벨을 찍으면 `등록된 스풀이 아니에요` (라벨은 떼서 버림). 등록 · 정보 고치기는 PC 에서만

- **정함**: 0g 필라멘트 줄도 그대로 저장 (`ProductDialog.tsx` save 의 줄 빼기 삭제). 필라멘트를 고르지 않은 빈 줄은 지금처럼 `필라멘트를 고르세요` 오류. 부자재 수량 0 줄은 이미 그대로 저장되고 있어 같은 규칙
- **반영할 곳**: PRD 3.6 · screens.md 2.5 · ProductDialog.tsx · 테스트
