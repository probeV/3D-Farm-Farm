## 돈을 보는 두 관점

손익 화면 하나에서 위쪽 `현금 기준` / `손익 기준` 으로 바꿔 본다. 두 관점은 필라멘트 · 장비를 가져오는 곳이 달라 서로 겹치지 않는다.

| 항목 | 현금 기준 (통장) | 손익 기준 (쓴 만큼) |
|---|---|---|
| 매출 | 판매 장부 | 판매 장부 |
| 필라멘트 | 지출 장부 — **산 날** | **사용 시작한 스풀**의 구매가 (사용 시작일 기준). 구매가가 없으면 색상 가격 → 필라멘트 가격 |
| 부자재 | 지출 장부 — 산 날 | 지출 장부 — 산 날 (현금 기준과 같음) |
| 운영비 (소모품 · 구독 · 판매비 · 기타) | 지출 장부 | 지출 장부 |
| 장비 (`투자(장비)`) | 지출 장부 — 산 날 | 넣지 않음 → 투자 회수(PL-02)로 따로 |
| 함께 보는 것 | 누적 잔액 · 투자 회수 · 손익분기점 | 월 이익 |

- **제품 원가는 손익에 쓰지 않는다.** 제품 원가는 제품 정리 · 판매가 정하기용이고, 손익은 실제 기록(판매 · 지출 · 스풀)으로만 계산한다
- 스풀 방식이라 실패 출력 · 테스트 출력 · 자투리도 따로 계산하지 않아도 손익에 들어간다
- **감가상각은 하지 않는다.** 장비값은 손익에서 빼고 회수율로 본다 (회사의 EBITDA · 회수 기간과 같은 방식). 세금 신고용 감가상각은 세무 쪽에서
- 부자재는 아직 금액이 작아 손익 기준도 산 날로 본다. 관리할 필요가 생기면 스풀처럼 묶음을 뜯은 날(사용 시작) 기준으로 바꾼다

## 기능

### 판매 장부 — `SALE`

| ID | 기능 | 내용 |
|---|---|---|
| SALE-01 | 판매 목록 | 날짜 · 판매처(스마트스토어 · 직접 판매 등) · 제품 · 수량 · 판매가 · 수수료 · 배송비 · 정산 금액 |
| SALE-02 | 판매 추가 / 수정 / 삭제 | 제품은 등록된 제품에서 고른다. 판매가 · 수수료는 제품 · 제품 원가 설정(SET-06 · 07)에서 기본값, 고칠 수 있음 |
| SALE-04 | 한 주문에 여러 제품 | 주문 하나에 제품 여러 줄 (배송비 · 포장비는 주문 단위) |

### 손익 — `PL`

| ID | 기능 | 내용 |
|---|---|---|
| PL-01 | 손익 (월 · 연) | `현금 기준` / `손익 기준` 전환 (위 "돈을 보는 두 관점"). 아래 계산 순서. 기간 선택 |
| PL-02 | 투자 회수 | 누적 투자금(`투자(장비)` 합계) · 누적 순이익(손익 기준) · **회수율** (누적 순이익 ÷ 누적 투자금) |
| PL-03 | 손익분기점 | 개당 평균 이익 기준 "앞으로 N개 더 팔면 회수" |
| PL-04 | 월별 그래프 | 월별 매출 · 비용 · 이익 막대 |
| PL-06 | 세금 | 종합소득세 등 낸 세금을 지출로 기록해 순이익에서 뺀다. 지출 분류(EXP-03)에 `세금` 추가 |

#### 계산 순서

손익 기준:
```
매출액                 판매 장부의 판매가 합계
− 재료비               사용 시작한 스풀 구매가 + 부자재 지출
= 매출총이익
− 운영비               수수료 · 택배비 · 광고비 · 구독 · 소모품 · 기타 (장비 제외)
= 영업이익
± 영업외 손익           이자 수입 · 이자 비용 등
− 세금                 종합소득세 등
= 순이익
```

현금 기준: `들어온 돈(판매 정산 금액) − 나간 돈(지출 장부 전부, 장비 포함)` 월별 + 누적 잔액

#### 구현 방식 (안)

> 목업을 만들어 보고 다시 판단한다.

- **새로 저장하는 것 없음.** 손익 화면은 기간을 고르면 아래 세 기록을 분류 조건으로 더하기만 한다. 지출 장부의 **분류(EXP-03)** 가 핵심

| 기록 | 입력하는 곳 | 손익에서 쓰는 값 |
|---|---|---|
| `Expense` (지출) | 지출 장부 (v1.2.0) | 날짜 · 분류 · 금액 |
| `Sale` (판매) | 판매 장부 | 날짜 · 판매가 · 수수료 · 정산 금액 |
| `Spool` (스풀, 이미 있음) | 필라멘트 화면 | 구매가 · 사용 시작일(`opened_at`) |

```
현금 기준 (기간)   = Sale 정산 금액 합계 − Expense 합계 (모든 분류)
손익 기준 (기간)   = Sale 판매가 합계
                   − 그 기간에 사용 시작한 Spool 구매가 합계 (없으면 색상 → 필라멘트 가격)
                   − Expense 합계 (분류가 `투자(장비)` · `필라멘트` 가 아닌 것)
투자 회수 (PL-02)  = 처음부터 지금까지 손익 기준 이익 합계 ÷ `투자(장비)` 지출 합계
```

- "장비를 손익에서 뺀다" = 손익 기준을 더할 때 `투자(장비)` 분류를 조건으로 빼는 것. 장비값은 현금 기준(산 달에 그대로)과 투자 회수(남은 금액)에서 보인다
  - 예: 1월 프린터 120만 원, 매달 매출 50만 · 재료비 + 운영비 30만 → 손익 기준 월 이익은 매달 20만, 투자 회수는 1월 17% → 2월 33% → 3월 50%
- 화면 모양 (안):
  ```
  [손익]   기간: 2026년 1월 ▾      [현금 기준 | 손익 기준]

  ┌ 투자 회수 50% ┐ ┌ 이번 달 이익 ┐ ┌ 누적 잔액 ┐
  └ 남은 60만      ┘ └ 20만          ┘ └ ...        ┘

  매출            500,000
  − 재료비        200,000   (스풀 3개 · 부자재)
  − 운영비        100,000
  = 이익          200,000

  [월별 막대 그래프]
  ```

- **부가세는 비용이 아니다**: 손님에게 받아 대신 내는 돈이라 손익에서 뺀다. 간이과세자면 처리가 달라 사업자 유형에 맞춘다

### 스마트스토어 연동 — `STORE`

| ID | 기능 | 내용 |
|---|---|---|
| STORE-01 | 정산 엑셀 올리기 | 판매자센터에서 받은 주문 · 정산 엑셀을 올리면 판매 장부로 (판매가 · 수수료 · 정산 금액) |
| STORE-02 | 상품 연결 | 스토어 상품(옵션)과 이 앱의 제품을 한 번 짝지어 두고, 다음부터 자동으로 |
| STORE-03 | 커머스 API | 주문 · 정산 조회 API 로 자동 가져오기. 엑셀 올리기가 자리 잡은 뒤에 (API 사용 신청 · 인증 필요) |

- 스마트스토어는 매출 · 수수료까지만 준다. 원가 · 다른 비용 · 손익은 이 앱에서 계산한다

### TBD-18 QR 스풀 관리 (라벨 발급 · 출력 · 찍어서 등록)

- **지금**: 스풀 코드(`S00001`)는 DB id 와 따로 `code_no` 로 저장해 라벨용으로 대비해 두었고, 코드로 스풀 찾기(INV-09)가 있다. QR 라벨 · 스캔 기능은 없다.
- **하려는 것** (PRD 5장 "QR 스풀 관리"):
  ```
  라벨 발급(번호만 예약·인쇄) → 스풀에 붙이기 → 찍어서 등록(색상·구매가 연결) → 찍어서 사용 시작 / 사용 완료
  ```
  - 발급: "라벨 N장" → 다음 번호부터 N개 예약(예: S00101~S00150, 시작 번호 지정 가능). 스풀 행은 만들지 않고 번호 범위만 기록(`LabelBatch`). 같은 묶음 다시 인쇄, 발급 안 한 번호를 찍으면 거부
  - 출력: QR + 코드 라벨 (예: 40×30mm)
  - 등록: 회사 → 필라멘트 → 색상 · 구매가 · 구매일을 한 번 정해 두고 같은 색 스풀을 연속으로 찍기. 결과는 목록에 쌓이고 줄마다 취소, 이미 등록된 코드는 "이미 등록됨"
  - 모드: `등록` · `사용 시작` · `사용 완료` · `조회` 중 골라서 찍기 (자동으로 다음 상태로 넘기지 않음 — 실수 방지)
  - 라벨 없이 등록: 지금의 재고 추가 그대로 (라벨과 같은 번호 순서)
- **정할 것**:
  - 라벨 출력 방법 — 라벨 프린터(기종 · 라벨 크기) / 일반 프린터 + A4 라벨지(한 장에 몇 칸) / 브라우저 인쇄로 충분한지
  - 찍는 도구 — 무엇부터: USB 2D 리더기(키보드처럼 입력) / 직접 입력 / 폰 카메라(QR 안에 주소를 넣으면 PC 주소 고정 필요)
  - QR 안에 넣을 것 — 코드만(`S00105`) / 주소(`http://…/spools/S00105`)
  - 발급 기록(`LabelBatch`)을 둘지, 번호 예약 없이 "다음 번호부터 N장 인쇄"만 할지
  - 화면 위치 — 필라멘트 화면 안 `QR` 버튼 / 사이드바 메뉴 따로
  - 등록 후 회사 · 색상이 들어간 라벨을 다시 뽑는 기능을 넣을지
- **반영할 곳**: PRD 3.4 · 3.5 · 5장 · ERD(`LabelBatch`) · api.md · screens.md 1장 · 목업 · 서버(`services.py` 로 스캔 동작 공통화, architecture.md 2장) · 화면
