### TBD-18 QR 스풀 관리 (라벨 발급 · 출력 · 찍어서 등록)

- **지금**: 스풀 코드(`S00001`)는 DB id 와 따로 `code_no` 로 저장해 라벨용으로 대비해 두었고, 코드로 스풀 찾기(INV-09)가 있다. QR 라벨 · 스캔 기능은 없다.
- **하려는 것** (PRD 5장 "QR 스풀 관리"):
  ```
  라벨 발급(번호만 예약·인쇄) → 스풀에 붙이기 → 찍어서 등록(색상·구매가 연결) → 찍어서 사용 시작 / 사용 완료
  ```
  - 발급: "라벨 N장" → 다음 번호부터 N개 예약(예: S00101~S00150, 시작 번호 지정 가능). 스풀 행은 만들지 않고 번호 범위만 기록(`LabelBatch`). 같은 묶음 다시 인쇄, 발급 안 한 번호를 찍으면 거부
  - 출력: QR + 코드 라벨 (예: 40×30mm)
  - 등록: 회사 → 필라멘트 → 색상 · 구매가 · 구매일을 한 번 정해 두고 같은 색 스풀을 연속으로 찍기. 결과는 목록에 쌓이고 줄마다 취소, 이미 등록된 코드는 "이미 등록됨"
  - 모드: `등록` · `사용 시작` · `사용 완료` · `조회` 중 골라서 찍기 (자동으로 다음 상태로 넘기지 않음 — 실수 방지)
  - 라벨 없이 등록: 지금의 재고 추가 그대로 (라벨과 같은 번호 순서)
- **정할 것**:
  - 라벨 출력 방법 — 라벨 프린터(기종 · 라벨 크기) / 일반 프린터 + A4 라벨지(한 장에 몇 칸) / 브라우저 인쇄로 충분한지
  - 찍는 도구 — 무엇부터: USB 2D 리더기(키보드처럼 입력) / 직접 입력 / 폰 카메라(QR 안에 주소를 넣으면 PC 주소 고정 필요)
  - QR 안에 넣을 것 — 코드만(`S00105`) / 주소(`http://…/spools/S00105`)
  - 발급 기록(`LabelBatch`)을 둘지, 번호 예약 없이 "다음 번호부터 N장 인쇄"만 할지
  - 화면 위치 — 필라멘트 화면 안 `QR` 버튼 / 사이드바 메뉴 따로
  - 등록 후 회사 · 색상이 들어간 라벨을 다시 뽑는 기능을 넣을지
- **반영할 곳**: PRD 3.4 · 3.5 · 5장 · ERD(`LabelBatch`) · api.md · screens.md 1장 · 목업 · 서버(`services.py` 로 스캔 동작 공통화, architecture.md 2장) · 화면

### TBD-30 포장 세트 · 부자재 세트 (v1.1.0 TBD-17 · 22 에서 남김)

- **지금**: 제품의 사용 부자재는 제품마다 한 줄씩 넣는다. 다른 제품의 부자재 항목을 가져오는 `+ 다른 제품에서` 는 있다 (수량은 직접, v1.1.0 TBD-22).
- **하려는 것**: 같은 조합(예: 박스 + 완충재 + 테이프, 자석 12개 + OPP 봉투 + 스티커)을 이름 붙여 두고 제품마다 고르기.
  세트를 고치면 쓰는 제품이 모두 바뀌게 할지(연결) / 넣을 때만 복사할지는 그때 정하기
- **언제**: 같은 조합을 여러 제품에 반복해 넣는 일이 실제로 많아지면. 그전에는 `+ 다른 제품에서` 로 충분
- **반영할 곳**: PRD 3.6 · 3.7 · ERD · api.md · screens.md 2.5 · 3장 · 목업 · 서버 · 화면

### TBD-31 스풀 · 부자재 구매를 지출과 잇기 (v1.2.0 에서 남김)

- **지금**: 지출 장부(PRD 3.10)와 스풀 재고 추가(INV-02) · 부자재 구매가를 따로 입력한다. 같은 구매를 두 번 적게 된다.
  v1.2.0 에서는 지출은 주문 단위(배송비 포함 · 여러 색 한 번에), 스풀은 한 통 단위라 맞지 않아 잇지 않았다.
- **하려는 것**: 재고 추가 창에서 `지출에도 넣기` (주문 하나 = 지출 한 줄, 분류 `필라멘트`) / 지출 창에서 `스풀로 넣기` 중 하나
- **정할 것**: 어느 쪽에서 넣을지 · 한 주문에 여러 색 · 배송비를 스풀 구매가에 나눠 넣을지 · 나중에 한쪽을 고치면 다른 쪽도 바꿀지
- **언제**: 두 번 입력이 실제로 번거로워지면 (v2 손익의 현금 기준은 지출, 손익 기준은 스풀 구매가를 쓰므로 둘 다 정확해야 한다)
- **반영할 곳**: PRD 3.4 · 3.10 · ERD · api.md · screens.md 1.7 · 5장 · 서버 · 화면

### TBD-32 사용량 0g 필라멘트 줄도 저장 (사용하면서 불편)

- **지금**: 제품 저장 시 사용량이 0 인 필라멘트 줄은 빼고 저장한다 (줄이 하나뿐이면 남김, `ProductDialog.tsx` save). 서버 · 입력 검사는 0 을 허용한다.
- **불편**: 색상만 먼저 골라 두고 g 은 나중에 넣으려 해도, 저장하면 그 줄이 사라져서 다시 골라야 한다.
- **하려는 것**: 0g 줄도 그대로 저장 (원가 계산은 지금처럼 `필라멘트 사용량 미입력` 경고)
- **정할 것**: 필라멘트를 고르지 않은 빈 줄은 어떻게 할지 (지금도 `필라멘트를 고르세요` 오류) · 부자재 수량 0 줄도 같은 규칙으로 할지
- **반영할 곳**: PRD 3.6 · screens.md 2.5 · ProductDialog.tsx · 테스트
