### TBD-18 QR 스풀 관리 (라벨 발급 · 출력 · 찍어서 등록)

- **지금**: 스풀 코드(`S00001`)는 DB id 와 따로 `code_no` 로 저장해 라벨용으로 대비해 두었고, 코드로 스풀 찾기(INV-09)가 있다. QR 라벨 · 스캔 기능은 없다.
- **하려는 것** (PRD 5장 "QR 스풀 관리"):
  ```
  라벨 발급(번호만 예약·인쇄) → 스풀에 붙이기 → 찍어서 등록(색상·구매가 연결) → 찍어서 사용 시작 / 사용 완료
  ```
  - 발급: "라벨 N장" → 다음 번호부터 N개 예약(예: S00101~S00150, 시작 번호 지정 가능). 스풀 행은 만들지 않고 번호 범위만 기록(`LabelBatch`). 같은 묶음 다시 인쇄, 발급 안 한 번호를 찍으면 거부
  - 출력: QR + 코드 라벨 (예: 40×30mm)
  - 등록: 회사 → 필라멘트 → 색상 · 구매가 · 구매일을 한 번 정해 두고 같은 색 스풀을 연속으로 찍기. 결과는 목록에 쌓이고 줄마다 취소, 이미 등록된 코드는 "이미 등록됨"
  - 모드: `등록` · `사용 시작` · `사용 완료` · `조회` 중 골라서 찍기 (자동으로 다음 상태로 넘기지 않음 — 실수 방지)
  - 라벨 없이 등록: 지금의 재고 추가 그대로 (라벨과 같은 번호 순서)
- **정할 것**:
  - 라벨 출력 방법 — 라벨 프린터(기종 · 라벨 크기) / 일반 프린터 + A4 라벨지(한 장에 몇 칸) / 브라우저 인쇄로 충분한지
  - 찍는 도구 — 무엇부터: USB 2D 리더기(키보드처럼 입력) / 직접 입력 / 폰 카메라(QR 안에 주소를 넣으면 PC 주소 고정 필요)
  - QR 안에 넣을 것 — 코드만(`S00105`) / 주소(`http://…/spools/S00105`)
  - 발급 기록(`LabelBatch`)을 둘지, 번호 예약 없이 "다음 번호부터 N장 인쇄"만 할지
  - 화면 위치 — 필라멘트 화면 안 `QR` 버튼 / 사이드바 메뉴 따로
  - 등록 후 회사 · 색상이 들어간 라벨을 다시 뽑는 기능을 넣을지
- **반영할 곳**: PRD 3.4 · 3.5 · 5장 · ERD(`LabelBatch`) · api.md · screens.md 1장 · 목업 · 서버(`services.py` 로 스캔 동작 공통화, architecture.md 2장) · 화면
