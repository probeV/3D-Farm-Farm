### TBD-18 QR 스풀 관리 (라벨 발급 · 출력 · 찍어서 등록)

- **지금**: 스풀 코드(`S00001`)는 DB id 와 따로 `code_no` 로 저장해 라벨용으로 대비해 두었고, 코드로 스풀 찾기(INV-09)가 있다. QR 라벨 · 스캔 기능은 없다.
- **하려는 것** (PRD 5장 "QR 스풀 관리"):
  ```
  라벨 발급(번호만 예약·인쇄) → 스풀에 붙이기 → 찍어서 등록(색상·구매가 연결) → 찍어서 사용 시작 / 사용 완료
  ```
  - 발급: "라벨 N장" → 다음 번호부터 N개 예약(예: S00101~S00150, 시작 번호 지정 가능). 스풀 행은 만들지 않고 번호 범위만 기록(`LabelBatch`). 같은 묶음 다시 인쇄, 발급 안 한 번호를 찍으면 거부
  - 출력: QR + 코드 라벨 (예: 40×30mm)
  - 등록: 회사 → 필라멘트 → 색상 · 구매가 · 구매일을 한 번 정해 두고 같은 색 스풀을 연속으로 찍기. 결과는 목록에 쌓이고 줄마다 취소, 이미 등록된 코드는 "이미 등록됨"
  - 모드: `등록` · `사용 시작` · `사용 완료` · `조회` 중 골라서 찍기 (자동으로 다음 상태로 넘기지 않음 — 실수 방지)
  - 라벨 없이 등록: 지금의 재고 추가 그대로 (라벨과 같은 번호 순서)
- **정할 것**:
  - 라벨 출력 방법 — 라벨 프린터(기종 · 라벨 크기) / 일반 프린터 + A4 라벨지(한 장에 몇 칸) / 브라우저 인쇄로 충분한지
  - 찍는 도구 — 무엇부터: USB 2D 리더기(키보드처럼 입력) / 직접 입력 / 폰 카메라(QR 안에 주소를 넣으면 PC 주소 고정 필요)
  - QR 안에 넣을 것 — 코드만(`S00105`) / 주소(`http://…/spools/S00105`)
  - 발급 기록(`LabelBatch`)을 둘지, 번호 예약 없이 "다음 번호부터 N장 인쇄"만 할지
  - 화면 위치 — 필라멘트 화면 안 `QR` 버튼 / 사이드바 메뉴 따로
  - 등록 후 회사 · 색상이 들어간 라벨을 다시 뽑는 기능을 넣을지
- **반영할 곳**: PRD 3.4 · 3.5 · 5장 · ERD(`LabelBatch`) · api.md · screens.md 1장 · 목업 · 서버(`services.py` 로 스캔 동작 공통화, architecture.md 2장) · 화면

### TBD-04 제품에서 쓰는 색상을 지울 때 (FIL-09 보완)

- **배경**: 제품의 사용 필라멘트 줄마다 색상을 고르게 되면서(제품 원가 목업), 제품이 필라멘트의 색상을 직접 가리킨다.
  지금 규칙(FIL-09)은 "스풀이 있으면 색상 삭제 불가" 뿐이라, 스풀이 없는 색상은 제품에서 쓰고 있어도 지워지고 제품 쪽 연결이 끊긴다.
- **결정**: 막지 않고 **경고 후 허용**. 삭제하면 그 제품 줄은 `색상 선택 안 함` 이 되고 필라멘트 가격으로 계산한다.
  - 기준: 지우면 원가를 아예 계산할 수 없는 것(제품에서 쓰는 필라멘트 · 부자재)은 삭제 불가, 덜 정확해질 뿐인 것(색상)은 경고 후 허용
- **확인 창** (조용히 바뀌지 않게). 다른 데이터가 바뀌는 삭제라 **2차 확인** (screens.md 공통 "삭제 확인"):
  ```
  레드 색상을 삭제할까요?
  제품 2개에서 이 색상을 쓰고 있어요: 분수 원판 세트, 소마 큐브
  삭제하면 이 제품들의 해당 줄은 '색상 선택 안 함'이 되고, 필라멘트 가격으로 계산돼요.
  (색상 가격이 따로 있던 색상이면) 원가가 바뀔 수 있어요.
  [취소] [삭제]  →  누르면  [취소] [정말 삭제]
  ```
- **반영할 곳**: ERD `ProductFilament.color → Color` = `SET_NULL` (반영함) · PRD FIL-09 · 필라멘트 화면의 색상 삭제 확인 창 (필라멘트 화면 작업 때)

### TBD-08 스풀이 있는 색상을 지울 때 (FIL-09 변경)

- **지금**: 색상에 스풀이 하나라도 있으면 삭제 불가 — 409 `스풀이 있어서 삭제할 수 없습니다.` (`Spool.color → Color` = `PROTECT`)
- **결정**: 막지 않고 **경고 후 허용**. 삭제하면 그 색상의 스풀도 모두 함께 지워진다.
- **확인 창**: 스풀 개수를 보여 주고 **2차 확인** (screens.md 공통 "삭제 확인"). 스풀도 없고 제품에서도 안 쓰면 지금처럼 한 번만 묻기:
  ```
  레드 색상을 삭제할까요?
  이 색상의 스풀 5개(재고 2 · 사용 중 1 · 사용 완료 2)도 함께 삭제돼요.
  삭제한 스풀은 되돌릴 수 없어요.
  [취소] [삭제]  →  누르면  [취소] [정말 삭제]
  ```
  - 제품에서 쓰는 색상이면 TBD-04 의 제품 안내도 같은 창에 함께 보여 준다
- **정할 것**: 되돌리기(7초 알림)를 둘지. 지금 되돌리기는 스풀 동작에만 있고(PRD 3.5), 색상 · 스풀을 한꺼번에 다시 만드는 기능은 없다
- **반영할 곳**: ERD `Spool.color → Color` = `PROTECT` → `CASCADE` (마이그레이션) · PRD FIL-09 · api.md 색상 삭제(409 → 204) ·
  `ColorViewSet.protected_message` 정리 · 2차 확인 대화상자(공통 부품, TBD-09) · 필라멘트 화면의 색상 삭제 확인 창 · 서버 · 화면 테스트

- **결정**: 목적은 제품 원가와 순마진율 파악이므로 단순하게 간다.
  - 이름은 `부자재` 그대로 (제조에서 부자재는 원재료 말고 만들고 내보내는 데 드는 재료 전체 — 포장재 포함)
  - **부자재 카테고리**를 둔다. 제품 카테고리처럼 직접 추가 · 수정 (처음에는 `부품` · `포장재` · `기타`). 카테고리 없이도 등록 가능 (미분류)
  - 제품의 사용 부자재 줄은 지금 그대로 — 박스 · 완충재도 제품마다 직접 골라 넣는다 (제품마다 다른 포장이 그대로 반영됨)
  - 제품 창 원가 내역에서 부자재비를 카테고리별로 나눠 보여 준다 (예: `부자재비 753원` 아래 `부품 720원 · 포장재 33원`). 목록 원가 열은 합계 그대로
  - 나눠 쓰는 부자재는 "1묶음으로 약 N회" 로 등록한다 (예: 테이프 1롤 = 약 40회 → 묶음 수량 40, 단위 `회`). 데이터 구조는 그대로, 부자재 창에 안내 문구만
- **나중에** (필요해지면): 같은 포장 조합을 여러 제품에 반복해 넣게 되면 포장 세트(포장 방식을 만들어 제품마다 고르기),
  한 주문에 여러 개를 보낼 때 포장비가 겹치는 문제는 스마트스토어 연동 때 실제 주문 기준으로
- **반영할 곳**: PRD 3.7 · 3.6 · ERD (`PartCategory`, `Part.category` → SET_NULL 또는 PROTECT 정하기) · api.md · screens.md 2.5 · 3장 ·
  목업(부자재 관리 창 분류 · 원가 내역 카테고리별) · 서버 · 화면

### TBD-22 제품 창 · 다른 제품에서 부자재 가져오기

- **지금**: 제품 창의 사용 부자재는 `+ 추가` 로 한 줄씩 넣는다. 같은 부자재 조합(예: 자석 12개 + OPP 봉투 + 스티커)을 여러 제품에 쓰는 경우가 많아 번거롭다.
- **결정**: 사용 부자재 표 머리에 `+ 다른 제품에서` 버튼. 제품을 고르면 그 제품의 부자재 줄을 수량까지 복사해 넣는다 (제품 복제의 재료 복사와 같은 동작). 넣은 뒤에는 보통 줄처럼 고치거나 뺄 수 있다. 데이터 구조는 그대로
  - 부자재 세트(이름 붙인 조합) · 세트 연결은 하지 않는다. 자주 쓰는 조합이 보이면 그때 다시 (TBD-17 의 포장 세트와 함께)
- **정할 것**: 이미 있는 부자재가 또 들어오면 수량을 합칠지 / 줄을 따로 둘지. 저장 전 미리보기(고른 제품의 부자재 목록)를 보여 줄지
- **반영할 곳**: screens.md 2.5 · 목업(products.html 제품 창) · 화면 (`MaterialLines`)

### TBD-23 부자재 한 번에 바꾸기 (A 부자재 → B 부자재)

- **배경**: 같은 부자재를 더 큰 묶음으로 사서 싸지는 경우가 있다 (예: 복사용지 400매 → 200매 묶음이 장당 더 쌈). 새 묶음을 부자재로 따로 추가하면, 예전 부자재를 쓰던 제품마다 제품 창에 들어가 하나씩 바꿔야 한다.
- **먼저 확인할 것**: 앞으로 새 묶음만 살 거면 **예전 부자재의 구매가 · 묶음 수량만 고치면** 쓰는 제품 원가가 모두 바로 바뀐다 (지금도 됨). 이 기능은 두 부자재를 모두 남겨 둘 때 (구매처가 다름, 예전 가격 기록 유지 등) 필요하다.
- **결정 (안)**: 부자재 수정 창의 `사용하는 제품` 목록 위에 `다른 부자재로 바꾸기`
  ```
  A 부자재 수정 창 → [다른 부자재로 바꾸기] → 바꿀 부자재 B 고르기
  → 쓰는 제품 목록 (기본 전체 선택, 체크로 뺄 수 있음) · 제품마다 이 부자재 금액 이전 → 이후 (지금의 금액 미리보기와 같은 모양)
  → [바꾸기] → 2차 확인 (다른 데이터가 바뀌는 동작, screens.md 공통 "삭제 확인" 과 같은 방식) → 실행
  → 알림 "제품 N개를 B 로 바꿨어요" · 다 바꿔서 A 를 쓰는 제품이 없으면 "A 를 삭제할까요?" 제안
  ```
  - 수량은 그대로 옮긴다. A 와 B 의 단위가 다르면 (예: `장` ↔ `묶음`) 경고하고 수량을 확인하게 한다
  - 그 제품에 이미 B 줄이 있으면 수량을 더해 한 줄로
  - 서버: 한 번에 처리하는 API (예: `POST /parts/{A}/replace/` `{to: B, products: [...]}`) — 하나라도 실패하면 아무것도 바꾸지 않음 (트랜잭션)
- **정할 것**: 위 흐름대로 할지, 제품 목록 선택 없이 "전부 바꾸기" 만 둘지
- **반영할 곳**: PRD 3.7 · api.md · screens.md 3.5 · 목업(parts.html 부자재 창) · 서버 · 화면 · 2차 확인 대화상자(TBD-09)
