# API — 3D Farm Farm (쓰리디팜팜)

> 요구사항: [PRD.md](PRD.md) · 데이터 구조: [ERD.md](ERD.md) · 코드 구조: [architecture.md](architecture.md)

화면(React)과 서버(Django REST Framework)가 주고받는 JSON API.
개발 중에는 Vite 개발 서버가 `/api` 요청을 Django 로 넘긴다. 브라우저로 `http://127.0.0.1:8000/api/v0/` 를 열면 목록을 직접 볼 수 있다 (재고 · 제품 · 지출 · 판매 · 손익 쪽 주소는 이 목록에 안 나오므로 `/api/v0/parts/` 처럼 직접 연다).

## 공통 규칙
| 항목 | 규칙 |
|---|---|
| 주소 | `/api/v0/...`. 주소·응답 모양이 바뀌는 변경은 `v1` 을 새로 만들고 `v0` 는 그대로 둔다 |
| 로그인 | 없음 (같은 와이파이 안에서만 쓰는 앱, PRD 1장) |
| 수정 | `PATCH` (바꿀 칸만 보냄). 전체 교체 `PUT` 은 쓰지 않음 (405) |
| 금액 · 무게 | 숫자. 소수점 아래가 0 이면 정수(`14400`, `1000`), 아니면 소수(`1000.5`). g당 가격은 소수 2자리(`14.4`). 원 단위 반올림은 화면에서 |
| 날짜 · 시각 | 날짜 `2026-10-20`, 시각 `2026-10-20T13:33:30+09:00` (서울 시간) |
| 목록 | 페이지 나눔 없이 전부 (데이터가 수백 건 수준). 검색 · 필터 · 정렬 · 요약 계산은 화면에서 |

### 오류 응답
| 상태 | 언제 | 모양 |
|---|---|---|
| 400 | 입력이 틀림 (본문 · 쿼리 파라미터 · 스풀 코드) | 칸별 한국어 메시지 `{"name": ["이미 있는 회사 이름입니다."]}` |
| 404 | 대상이 없음 (없는 id, 숫자가 아닌 id 포함) | `{"detail": "찾을 수 없습니다."}` |
| 409 | 다른 데이터가 쓰고 있어서 삭제 불가 (PRD FIL-09 · PRD-11 · PART-02) | `{"detail": "필라멘트가 있어서 삭제할 수 없습니다."}` |

- 오류 문구는 `~입니다` 체로 쓴다 (DRF 기본 문구 `이 필드는 필수 항목입니다.` 등도 같은 말투)

### 입력 검사 위치
| 입력 | 검사 | 틀리면 |
|---|---|---|
| 요청 본문 (JSON · multipart) | 시리얼라이저 | 400 |
| 쿼리 파라미터 (`?color=3&status=sealed`) | 시리얼라이저 (`SpoolFilterSerializer`) | 400 `{"color": ["유효한 정수를 입력하세요."]}` |
| 경로의 스풀 코드 (`/spools/code/S00012/`) | 시리얼라이저 (`SpoolCodeSerializer`) | 400 |
| 경로의 id (`/spools/12/`) | DRF 가 id 로 찾기 | 404 (숫자가 아니어도 JSON 404) |

## 회사 `brands`
```json
{ "id": 1, "name": "Bambu Lab", "logo": "/media/brands/bambu.png", "filament_count": 1 }
```
| 칸 | 쓰기 | 설명 |
|---|---|---|
| `name` | ✅ 필수 | 중복 불가 → 400 `이미 있는 회사 이름입니다.` |
| `logo` | 선택 | 대표 이미지(로고). 응답은 상대 주소 `/media/brands/...` 또는 `null` (없으면 화면에서 첫 글자 아이콘) |
| `filament_count` | — | 이 회사의 필라멘트 수 |

### 로고 올리기 · 지우기
| 하려는 것 | 요청 |
|---|---|
| 이름 + 로고로 추가 | `POST /brands/` — `multipart/form-data` 로 `name`, `logo`(파일) |
| 로고 바꾸기 | `PATCH /brands/{id}/` — `multipart/form-data` 로 `logo`(파일) |
| 로고 지우기 | `PATCH /brands/{id}/` — JSON `{"logo": null}` |
| 이름만 바꾸기 | `PATCH /brands/{id}/` — JSON `{"name": "..."}` (로고는 그대로) |

- png · jpg · webp 만, 5MB 까지 → 아니면 400 (`png, jpg, webp 이미지만 올릴 수 있습니다.` / `이미지는 5MB 까지 올릴 수 있습니다.`)
- 서버가 비율을 유지해 256×256 안으로 줄여 저장한다 (작은 이미지는 그대로, 형식도 그대로)
- 로고를 바꾸거나 지우거나 회사를 삭제하면 이전 파일도 지운다
- 삭제: 필라멘트가 있으면 409 `필라멘트가 있어서 삭제할 수 없습니다.` (로고 파일도 그대로)
- 목록 순서: 이름순

## 재질 `materials`
```json
{ "id": 1, "name": "PLA", "filament_count": 1 }
```
- `name` 중복 불가 → 400 `이미 있는 재질입니다.`
- 삭제: 필라멘트에서 쓰면 409 `필라멘트에서 쓰고 있어서 삭제할 수 없습니다.`

## 필라멘트 `filaments`
필라멘트 화면은 **이 목록 하나로 그린다.** 색상과 색상별 스풀 개수가 함께 온다.
전체 요약 · 회사별 kg · 검색 · 필터 · 정렬은 화면에서 이 데이터로 계산한다 (회사 이름 · 로고는 `brands` 목록에서).

```json
{
  "id": 1,
  "brand": 1, "brand_name": "Bambu Lab",
  "material": 1, "material_name": "PLA",
  "series": "Basic",
  "display_name": "Bambu Lab › PLA Basic",
  "price": 14400, "spool_g": 1000,
  "avg_held_price": 14400,
  "colors": [
    {
      "id": 1, "filament": 1, "name": "화이트", "hex": "#F5F5F5",
      "price": null, "spool_price": 14400, "held_price": null, "price_per_g": 14.4,
      "counts": { "sealed": 1, "open": 1, "empty": 0 }
    }
  ]
}
```
| 칸 | 쓰기 | 설명 |
|---|---|---|
| `brand` · `material` | ✅ 필수 | id |
| `series` | 선택 | 비우면 `""`. 회사 · 재질 · 시리즈 조합 중복 → 400 (`series` 칸에 메시지) |
| `price` | 선택 | 스풀 가격. `null` = 미입력 |
| `spool_g` | 선택 | 스풀 무게(g), 기본 1000 |
| `display_name` | — | `회사 › 재질 시리즈` |
| `avg_held_price` | — | 보유(재고 + 사용 중) 스풀 구매가 평균, 원 단위 반올림. 없으면 `null` (PRD INV-08) |
| `colors` | — | 색상 목록 (아래 색상과 같은 모양) |

- 삭제: 색상이 있으면 409 `색상이 있어서 삭제할 수 없습니다.`, 제품에서 쓰면 409 `제품에서 쓰고 있어서 삭제할 수 없습니다.`
- 목록 순서: 회사 이름 → 재질 이름 → 시리즈

### 화면에서 계산하는 값 (참고)
```
보유 kg (색상)      = (counts.sealed + counts.open) × spool_g ÷ 1000
회사별 상태별 kg    = 그 회사 필라멘트들의 Σ counts.상태 × spool_g ÷ 1000
재고 없는 색상      = sealed 0 이고 open 1 이상
소진된 색상         = sealed 0 이고 open 0
```

## 색상 `colors`
| 칸 | 쓰기 | 설명 |
|---|---|---|
| `filament` | ✅ 필수 | 필라멘트 id |
| `name` | ✅ 필수 | 같은 필라멘트 안에서 중복 → 400 `이 필라멘트에 같은 이름의 색상이 이미 있습니다.` |
| `hex` | ✅ 필수 | `F5F5F5` / `#f5f5f5` 모두 받아 `#F5F5F5` 로 저장. 형식이 틀리면 400 |
| `price` | 선택 | 등록 가격. 비우면(`null`) 필라멘트 가격을 따름. 지출이 바꾸지 않음 |
| `spool_price` | — | 원가 계산의 스풀 가격 = `held_price`, 없으면 등록 가격(색상 가격 → 필라멘트 가격) (v2 PL) |
| `held_price` | — | 보유 스풀(재고 · 사용 중, 구매가 있는 것) 구매가 평균, 원 단위. 없으면 `null` |
| `price_per_g` | — | g당 가격 (소수 2자리) |
| `counts` | — | 상태별 스풀 개수 `{sealed, open, empty}` |

- 삭제: 막는 것 없음 (204). 그 색상의 스풀도 함께 삭제되고, 제품에서 쓰던 줄은 `color: null`(색상 선택 안 함)이 되어 필라멘트 가격으로 계산된다 (PRD FIL-09).
  지우기 전 확인 창의 스풀 개수는 `counts`, "쓰는 제품" 목록은 화면이 제품 목록(`filaments[].color`)에서 찾는다

### 재고 추가 `POST /api/v0/colors/{id}/spools/`
지출 없이 들어온 스풀(선물 · 예전 재고)용. 산 스풀은 필라멘트 지출을 저장하면 생긴다 (아래 "지출" 구매 항목, TBD-33)
```json
{ "quantity": 3, "purchased_at": "2026-10-20", "price": 14400 }
```
| 칸 | 설명 |
|---|---|
| `quantity` | 1~100 (필수) |
| `purchased_at` | 비우면 오늘 |
| `price` | 스풀 1개 구매가. 비우면 색상의 `spool_price` |

- 응답 201: 만든 스풀 목록 (번호 순서, `buy: null`). 알림에 `S00041 ~ S00043` 처럼 범위를 보여줄 때 사용
- 번호는 항상 **다음 번호부터** — 지금까지 쓴 가장 큰 번호 + 1 (`SpoolNumber`). 지운 번호는 다시 쓰지 않는다 (번호 지정 없음, TBD-33)
  - 예: S00050 까지 있다가 S00050 을 지웠으면 다음은 S00051

## 스풀 `spools`
```json
{
  "id": 1, "code": "S00001", "code_no": 1, "color": 1,
  "status": "open", "price": 14000,
  "purchased_at": "2026-10-20",
  "opened_at": "2026-10-20T13:33:30+09:00", "finished_at": null,
  "note": "", "buy": 7, "label_printed": true
}
```
| 칸 | 쓰기 | 설명 |
|---|---|---|
| `code` | — | 스풀 코드 (`S` + 번호 5자리) |
| `code_no` | 만들 때만 | 비우면 다음 번호. 직접 정하는 건 되돌리기(지운 스풀을 같은 번호로 다시 만들기)용. 이미 있으면 400 `S00012 는 이미 있습니다.` · 만든 뒤에는 못 바꿈 (400) |
| `color` | ✅ 필수 | 색상 id |
| `status` | 선택 | `sealed`(재고) / `open`(사용 중) / `empty`(사용 완료) |
| `price` | 선택 | 구매가. `buy` 가 있는 스풀(지출로 생김)은 못 고침 → 400 `지출로 생긴 스풀은 구매가를 지출에서 고쳐요.` |
| `purchased_at` · `opened_at` · `finished_at` · `note` | 선택 | |
| `buy` | 만들 때만 | 주문 = 지출 구매 항목 id. 필라멘트 지출을 저장하면 정해진다. 만들 때 보내는 건 되돌리기용 · 만든 뒤에는 못 바꿈 (400 `주문은 바꿀 수 없습니다.`). `null` = 재고 추가로 넣은 스풀 |
| `label_printed` | 선택 | QR 라벨을 뽑았는지 (TBD-18). 새 스풀은 `false`, 보통은 아래 `labels` 로 바꾼다. 만들 때 보내는 건 삭제 되돌리기용 |

### 목록 `GET /api/v0/spools/?color=3&status=sealed`
- `color`(정수), `status`(`sealed` / `open` / `empty`) 로 거를 수 있다 (스풀 선택 · 조정 창). 번호 순서
- 형식이 틀리면 400: `?color=abc` → `{"color": ["유효한 정수를 입력하세요."]}`, `?status=lost` → `{"status": ["\"lost\"은 유효하지 않은 선택입니다."]}`

### 상태 바꾸기 `PATCH /api/v0/spools/{id}/`
| 보내는 것 | 동작 |
|---|---|
| `{"status": "open"}` (상태만) | 날짜 규칙 자동 적용 (PRD 3.4): 재고 → 날짜 지움 / 사용 중 → 시작일 없으면 지금, 완료일 지움 / 사용 완료 → 시작일 없으면 지금, 완료일 지금 |
| `{"status": "sealed", "opened_at": null, "finished_at": null}` (날짜 포함) | 보낸 값 그대로 저장 — 되돌리기 · 세부 조정에서 사용 |

### 그 밖
| 요청 | 설명 |
|---|---|
| `POST /api/v0/spools/` | 스풀 1개 만들기. **삭제 되돌리기**: 지운 스풀의 내용(`code_no` 포함)을 그대로 보내면 같은 코드로 다시 생김 |
| `DELETE /api/v0/spools/{id}/` | 삭제 (204) |
| `DELETE /api/v0/spools/?ids=3,4,5` | 쉼표로 구분한 id, 한 번에 100개까지 → `{"deleted": 3}`. **재고 추가 되돌리기**. 형식이 틀리거나 100개를 넘으면 400 |
| `GET /api/v0/spools/code/S00012/` | 코드로 찾기 (대소문자 무관). 형식이 틀리면 400, 없으면 404 (PRD INV-09). 폰 스풀 화면(INV-11)이 쓰므로 스풀 칸에 더해 `color_name` · `color_hex` · `filament_name`(`Bambu Lab › PLA Basic`) · `order`(`{"expense": 31, "date": "2026-10-27", "name": "PLA Basic 10롤"}`, 재고 추가로 넣은 스풀이면 `null`)를 준다 |

### QR 라벨 `GET · POST /api/v0/spools/labels/` (v2 TBD-18)
| 요청 | 설명 |
|---|---|
| `GET` | `{"public_url": "http://192.168.0.10:5173"}` — QR 안의 주소 앞부분 (`backend/.env` 의 `PUBLIC_URL`, 끝의 `/` 뺌). 없으면 `""` → 화면이 지금 연 주소를 쓴다. QR 안의 주소 = `{앞부분}/s/{코드}` (화면의 폰 스풀 화면) |
| `POST {"ids": [3, 4], "printed": true}` | 인쇄한 스풀을 `라벨 뽑음` 으로 → `{"updated": 2}`. `printed: false` 는 되돌리기. `ids` 는 1~500개, 틀리면 400 `{"ids": [...]}` |

- 라벨 인쇄 화면은 모든 스풀(`GET /spools/`) + 필라멘트 목록으로 그린다. `라벨 없음` = `label_printed` 가 `false` 이고 사용 완료가 아닌 스풀

## 되돌리기 (PRD 3.5) — 화면이 하는 일
서버는 이력을 저장하지 않는다. 방금 받은 응답을 화면이 기억해 두었다가 알림의 `되돌리기`(7초)에서 반대 요청을 보낸다.

| 방금 한 동작 | 되돌리기 요청 |
|---|---|
| 재고 추가 | `DELETE /spools/?ids=…` — 응답으로 받은 스풀 id 들 |
| 상태 변경 | `PATCH /spools/{id}/` — 바꾸기 전의 `status` · `opened_at` · `finished_at` 를 함께 |
| 스풀 삭제 | `POST /spools/` — 지우기 전에 갖고 있던 스풀 내용 그대로 (`code_no` · `label_printed` 포함) |
| 라벨 인쇄 | `POST /spools/labels/` — 인쇄한 스풀 id 들, `printed: false` (인쇄 창을 취소했을 때) |

# 재고 관리 (v2 STOCK)

재고 관리 화면의 부속품 · 포장 · 소모품 탭은 **품목 목록(`/parts/`) + 카테고리 + 포장 세트 + 제품 목록** 으로 그린다 (필라멘트 탭은 위 필라멘트 API).
탭별 카드 · 표 · 부족 알림 · 남은 금액 · 세트 원가 · 바로 쌀 수 있는 수는 화면에서 계산한다.
남은 수량은 **처음 등록 · 조정 · 다 씀 · 판매 저장 · 지출 구매 항목**(TBD-31)에서만 바뀌고, 바뀔 때마다 입출고 기록이 한 줄 남는다.

## 재고 품목 `parts`
```json
{
  "id": 1, "kind": "part", "name": "네오디뮴 자석 6×3mm", "category": 1,
  "photo": "/media/parts/magnet.png", "shop": "알리", "buy_url": "https://…",
  "price": 12000, "pack_qty": 200, "unit": "개", "unit_price": 60.0, "avg_price": 60.0,
  "stock": 1240, "alert": 200, "note": "N52",
  "product_count": 2, "set_count": 0, "last_used": null, "bought": true
}
```
| 칸 | 쓰기 | 설명 |
|---|---|---|
| `kind` | 추가할 때만 | 탭 `part`(부속품, 기본) · `pack`(포장재) · `supply`(소모품). 수정에서 바꾸면 400 `종류는 바꿀 수 없습니다.` |
| `name` | ✅ 필수 | 품목. 탭이 달라도 중복 불가 → 400 `이미 있는 품목입니다.` |
| `category` | 선택 | 같은 탭의 카테고리 id. 다른 탭 것이면 400 `같은 탭의 카테고리를 고르세요.` `null` = 미분류 |
| `photo` | 선택 | 사진. 회사 로고와 같은 방식 — multipart 로 파일, JSON `null` 로 지우기. 512×512 안으로 줄여 저장 |
| `shop` · `note` | 선택 | 회사/구매처, 메모 |
| `buy_url` | 선택 | 구매 링크 (최대 500자). 주소 형식이 아니면 400 `https:// 로 시작하는 주소로 입력하세요.` |
| `price` | 선택 | 묶음 구매가. `null` = 미입력 (원가에서 0원 + 경고). 소모품은 참고용 (원가에 안 씀) |
| `pack_qty` | 선택 | 묶음 수량, 기본 1. 0 보다 커야 함 |
| `unit` | 선택 | 단위, 기본 `개` |
| `stock` | 추가할 때만 | 지금 남은 수량, 기본 0 (소수 2자리). 0 이 아니면 입출고 기록 `조정 · 처음 수량`. 그 뒤로는 조정 · 다 씀으로만 — 수정에서 보내면 400 `남은 수량은 조정으로 바꾸세요.` 0 아래도 될 수 있다 (판매를 먼저 넣었을 때) |
| `alert` | 선택 | 부족 알림 기준, 기본 0. 남은 수량 ≤ 이 값이면 `부족`, ≤ 0 이면 `없음` (화면에서 계산) |
| `unit_price` | — | 개당 단가 = **평균 단가** (원가 계산 · 판매 포장 줄 · 손익, 소수 2자리). 평균이 없으면 직접 넣은 `price ÷ pack_qty`, 둘 다 없으면 `null` |
| `avg_price` | — | 평균 단가(이동평균, PRD EXP-08 아래). 없으면 `null` |
| `product_count` · `set_count` | — | 이 품목을 쓰는 제품 수 (부속품) · 포장 세트 수 (포장재) |
| `last_used` | — | 마지막으로 `다 씀` 한 날 (소모품). 없으면 `null` |
| `bought` | — | 지출로 산 적이 있는지. `true` 면 `price` · `pack_qty` 는 쓰지 않고(단가는 평균), 수정에서 다른 값을 보내면 400 `지출로 산 품목은 지출에서 바꾸세요.` |

- 목록: `?kind=part` 처럼 탭 하나만 (없는 값이면 400). 없으면 전부. 순서: 품목 이름순
- 삭제: 제품에서 쓰면 409 `제품에서 쓰고 있어서 삭제할 수 없습니다.` · 포장 세트에서 쓰면 409 `포장 세트에서 쓰고 있어서 삭제할 수 없습니다.`
  입출고 기록은 함께 삭제. 지난 판매의 포장 줄은 남는다 (팔 때 이름 · 단가)

### 조정 `POST /api/v0/parts/{id}/adjust/`
```json
{ "mode": "set", "qty": 64, "note": "재고 실사" }
```
- `mode`: `set` 실제 수량으로 맞추기 · `sub` 빼기 · `add` 더하기. 그 밖이면 400 `맞추기 · 빼기 · 더하기 중에서 고르세요.`
- `qty`: 0 이상 (빼기 · 더하기는 0 보다 커야 함 → 400 `0 보다 큰 수량을 넣으세요.`). `note`: 사유 (선택, 180자)
- 응답 200: 바뀐 품목 (위와 같은 모양). 맞추기로 같은 수량이면 기록을 남기지 않는다

### 다 씀 `POST /api/v0/parts/{id}/use/`
```json
{ "note": "막힘" }
```
- 소모품만 (아니면 400 `소모품만 다 씀으로 뺄 수 있습니다.`). 남은 수량 −1, 기록 `다 씀` (사유가 있으면 `다 씀 (막힘)`)
- 응답 200: 바뀐 품목 (`last_used` 가 오늘)

### 입출고 기록 `GET /api/v0/parts/{id}/history/`
```json
[
  { "id": 9, "date": "2026-11-10", "kind": "sale", "qty": -1, "after": 8, "note": "판매 · USB 무드등", "sale": 31, "expense": null, "created_at": "…" },
  { "id": 4, "date": "2026-11-02", "kind": "adjust", "qty": -3, "after": 9, "note": "찌그러져서 버림", "sale": null, "expense": null, "created_at": "…" }
]
```
- `kind`: `buy`(지출 구매 항목) · `sale`(판매) · `use`(다 씀) · `adjust`(조정 · 처음 수량). `qty` 는 늘면 +, 줄면 −. `after` = 그 뒤 남은 수량. `sale` · `expense` = 그 기록을 만든 판매 · 지출.
  입출고 기록은 그때의 개당 단가도 저장하지만(손익의 `쓴 만큼`, v2 PL) 이 목록에는 내보내지 않는다
- 순서: 날짜 최근순 (같은 날이면 나중에 넣은 것 먼저). 판매 · 지출을 지우면 그 기록은 `sale` · `expense` 가 `null` 이 되고 되돌리는 기록 `판매 삭제 · …` · `지출 삭제 · …` 이 더해진다 (판매 삭제는 판매 날짜로). 판매 날짜를 바꾸면 그 판매의 기록 날짜도 바뀐다

### 제품의 부속품 바꾸기 `POST /api/v0/parts/{id}/replace/`
```json
{ "to": 9, "products": [1, 3] }
```
- 제품에서 쓰는 이 부속품 줄을 `to` 로 바꾼다. `products` 를 빼면 이 부속품을 쓰는 제품 전부.
  주소는 `/parts/` 아래지만 제품의 줄을 바꾸는 동작이라 `products` 앱의 뷰
- 수량은 그대로. 그 제품에 이미 `to` 줄이 있으면 수량을 더해 한 줄로
- 한 번에 처리 (하나라도 실패하면 아무것도 바꾸지 않음). 부속품 자체는 지우거나 바꾸지 않는다
- 응답 200 `{"replaced": 2}` (바꾼 제품 수)
- 400: `to` 가 자기 자신 `다른 부자재를 고르세요.` · 없는 id `없는 부자재입니다.` · 부속품이 아님 `부속품만 고를 수 있습니다.` / `products` 에 이 부자재를 안 쓰는 제품 `이 부자재를 쓰는 제품을 고르세요.`

## 품목 카테고리 `part-categories`
```json
{ "id": 1, "kind": "part", "name": "부품", "part_count": 4 }
```
- `kind` 추가할 때만 (기본 `part`, 바꾸면 400 `종류는 바꿀 수 없습니다.`). `name` 필수, 같은 탭 안에서 중복 → 400 `이미 있는 카테고리 이름입니다.` (다른 탭엔 같은 이름 가능)
- `part_count` 는 이 카테고리의 품목 수. 목록: `?kind=` 로 탭 하나만. 순서: 탭 · 이름순
- 삭제: 막는 것 없음 (204). 그 품목은 `category: null`(미분류)
- 처음에는 부속품 `부품` · `기타`, 포장재 `포장재` (v1.1 마이그레이션이 만들고 v2 에서 `포장재` 를 포장 탭으로 옮김)

## 포장 세트 `pack-sets`
```json
{
  "id": 1, "name": "봉투 포장", "note": "키링 · 작은 소품",
  "lines": [{ "id": 1, "part": 3, "qty": 1 }, { "id": 2, "part": 7, "qty": 1 }],
  "product_count": 3
}
```
| 칸 | 쓰기 | 설명 |
|---|---|---|
| `name` | ✅ 필수 | 세트 이름. 중복 → 400 `이미 있는 세트 이름입니다.` |
| `note` | 선택 | 비고 |
| `lines` | ✅ 필수 | 들어가는 포장재 `{part, qty}`. 비어 있으면 400 `포장재를 한 개 이상 넣으세요.` 포장재가 아니면 `포장재만 고를 수 있습니다.` `qty` 0 보다 큼 (소수 2자리). 같은 포장재 줄은 수량을 합쳐 한 줄로 |
| `product_count` | — | 이 세트를 기본 포장으로 쓰는 제품 수 |

- 줄 저장은 제품 줄과 같다 — 보내면 통째로 바꾸고(줄 `id` 가 바뀜), 안 보내면 그대로
- 삭제: 기본 포장으로 쓰는 제품이 있으면 409 `기본 포장으로 쓰는 제품이 있어서 삭제할 수 없습니다.` 지난 판매의 포장 줄은 세트와 상관없음 (줄마다 복사)
- 세트를 고치면 기본 포장인 제품의 원가가 바로 바뀐다 (원가는 화면이 계산). 목록 순서: 이름순

### 화면에서 계산하는 값 (참고)
```
세트 원가           = Σ lines.qty × 품목.unit_price           (가격 없는 포장재는 0 + 경고)
바로 쌀 수 있는 수   = min( ⌊max(0, 품목.stock) ÷ lines.qty⌋ )   (가장 모자란 포장재 기준)
남은 금액           = Σ max(0, stock) × unit_price
상태               = stock ≤ 0 → 없음, stock ≤ alert → 부족
```

# 제품 원가

제품 원가 화면은 **제품 목록 + 필라멘트 목록(`/filaments/`) + 재고 품목 목록(`/parts/`) + 포장 세트(`/pack-sets/`) + 원가 설정** 으로 그린다.
원가 · 순이익 · 순마진율 · 권장 판매가 · 입력 필요 · 요약 · 정렬 · CSV 는 화면에서 계산한다 (PRD 3.6 원가 계산 규칙).
입력 중 미리보기(PRD-07)도 같은 계산을 쓰므로 서버에 따로 두지 않는다.

## 카테고리 `categories`
```json
{
  "id": 1, "name": "수업 교구", "product_count": 3,
  "subcategories": [{ "id": 1, "category": 1, "name": "수학", "product_count": 2 }]
}
```
| 칸 | 쓰기 | 설명 |
|---|---|---|
| `name` | ✅ 필수 | 중복 불가 → 400 `이미 있는 카테고리 이름입니다.` |
| `product_count` | — | 이 카테고리의 제품 수 (세부 분류에 있는 제품 포함) |
| `subcategories` | — | 세부 분류 목록 (이름순). 추가 · 수정 · 삭제는 `subcategories` 주소로 |

- 삭제: 제품이 있으면(세부 분류에만 있어도) 409 `제품이 있어서 삭제할 수 없습니다.` · 제품이 없으면 세부 분류도 함께 삭제
- 목록 순서: 이름순

## 세부 분류 `subcategories`
```json
{ "id": 1, "category": 1, "name": "수학", "product_count": 2 }
```
| 칸 | 쓰기 | 설명 |
|---|---|---|
| `category` | ✅ 만들 때만 | 카테고리 id. 만든 뒤에는 못 바꿈 → 400 `세부 분류의 카테고리는 바꿀 수 없습니다.` |
| `name` | ✅ 필수 | 같은 카테고리 안에서 중복 → 400 `이 카테고리에 같은 이름의 세부 분류가 이미 있습니다.` |
| `product_count` | — | 이 세부 분류의 제품 수 |

- 삭제: 제품이 있으면 409 `제품이 있어서 삭제할 수 없습니다.`

## 제품 `products`
```json
{
  "id": 1, "no": 1,
  "category": 1, "subcategory": 1,
  "name": "분수 원판 세트", "status": "on_sale",
  "print_minutes": 200, "sale_price": 18900, "default_pack": 1, "note": "",
  "filaments": [
    { "id": 1, "filament": 1, "color": 101, "grams": 24.37 },
    { "id": 2, "filament": 4, "color": null, "grams": 60 }
  ],
  "parts": [{ "id": 1, "part": 1, "qty": 12 }],
  "created_at": "2026-10-22T13:00:00+09:00", "updated_at": "2026-10-22T13:00:00+09:00"
}
```
| 칸 | 쓰기 | 설명 |
|---|---|---|
| `no` | 선택 | No. (1 이상). 비우면 지금 가장 큰 번호 + 1. 중복 → 400 `No. 3 는 이미 있습니다.` |
| `category` · `subcategory` | 선택 | id, `null` = 미분류 / 세부 분류 없음. 세부 분류는 그 카테고리 안의 것만 → 400 (`subcategory` 칸에 `세부 분류는 고른 카테고리 안에서 골라야 합니다.`) |
| `name` | ✅ 필수 | 제품명 |
| `status` | 선택 | `on_sale`(판매중) / `developing`(개발중, 기본) / `discontinued`(판매중지) |
| `print_minutes` | 선택 | 출력 시간(분, 정수). `null` = 미입력 |
| `sale_price` | 선택 | 판매가. `null` = 미입력 |
| `note` | 선택 | 메모 |
| `filaments` | 선택 | 사용 필라멘트 줄 `{filament, color, grams}`. `color` 는 선택(`null`), 그 필라멘트의 색상만 → 400 (`filaments[i].color`). `grams` 0 이상, 소수 2자리까지 |
| `default_pack` | 선택 | 기본 포장 세트 id (1개 보낼 때, STOCK-06). `null` = 입력 필요. 없는 id → 400 `없는 포장 세트입니다.` |
| `parts` | 선택 | 사용 부속품 줄 `{part, qty}`. `qty` 0 이상. 부속품(`kind: part`)만 → 아니면 400 `부속품만 고를 수 있습니다.` (포장은 `default_pack`) |

- **줄 저장**: `filaments` · `parts` 를 보내면 그 목록으로 통째로 바꾼다 (기존 줄을 지우고 새로 만들어서 줄 `id` 가 바뀐다).
  보내지 않으면 줄은 그대로 (`PATCH {"status": "discontinued"}` 처럼). 하나라도 틀리면 400, 아무것도 바뀌지 않음
- **복제** (PRD-04a): 서버 기능 없음. 화면이 원본을 복사해 추가 창에 채우고(`no` 는 비우거나 다음 번호, 이름 `(복사)`, 상태 `developing`) 저장할 때 `POST /products/`
- 삭제: 줄도 함께 삭제 (204). 팔린 적 있는 제품도 지울 수 있다 — 판매 줄은 남고 `product: null`, 팔 때 저장한 `product_name` 으로 보인다
- 목록 순서: No. 순 (숫자 순서)

### 화면에서 계산하는 값 (참고)
```
줄의 g당 가격 = 색상.spool_price(보유 스풀 평균 → 색상.price → 필라멘트.price) ÷ 필라멘트.spool_g      ← color 가 null 이면 필라멘트.price
             (색상.spool_price · price_per_g 가 이미 이 값. /filaments/ 의 colors 에 있음)
부속품비      = Σ qty × 품목.unit_price
포장비        = default_pack 세트 원가 (위 "포장 세트")
그 밖 원가 · 순이익 · 순마진율 · 권장 판매가 = PRD 3.6 원가 계산 규칙 (설정값은 cost-setting)
목록 색상     = filaments[].color 를 중복 없이 → 색상의 hex 로 동그라미
```

## 원가 설정 `cost-setting`
항상 1개라서 id 없이 주소 하나 (`GET` · `PATCH`, 처음 읽을 때 기본값으로 만들어짐). 바꾸면 모든 제품 원가에 바로 반영 (화면 계산).
```json
{
  "power_kw": 0.36, "elec_rate": 215, "fee_order": 1.98, "fee_sales": 2.73, "shipping_cost": 0, "target_margin": 40
}
```
| 칸 | 설명 (PRD 3.8) |
|---|---|
| `power_kw` | 프린터 소비 전력(kW). 0 이상, 소수 3자리 |
| `elec_rate` | 전기료 단가(원/kWh). 0 이상, 소수 1자리 |
| `fee_order` · `fee_sales` · `target_margin` | % 숫자 그대로 (`1.98` = 1.98%), 0 ~ 100, 소수 2자리 |
| `shipping_cost` | 건당 판매자 부담 배송비. 0 이상 정수 |

- `PUT` · `DELETE` 는 405
- 프린터 구매가 · 예상 수명 · 출력 실패율(`printer_price` · `printer_life_hours` · `failure_rate`)은 뺐다 (PRD 3.8). 보내도 무시한다

# 지출

지출 화면 = 지출 목록 + 반복 지출 (PRD 3.10). 요약 · 분류별 합계 · 기간 필터 · 이번 달에 넣을 반복 지출 · CSV 는 화면이 계산한다.
분류(`category`)는 고정 9개: `invest`(장비) · `filament`(필라멘트) · `part`(부속품) · `pack`(포장재) · `supply`(소모품) · `sub`(구독 · 운영) · `sell`(판매비) · `tax`(세금, v2 PL-06) · `etc`(기타). 다른 값은 400 `없는 분류입니다.`
키는 v1.2.0 그대로라 기존 `부자재` 지출은 `부속품` 이 된다 (v2 TBD-31).

## 지출 `expenses`
```json
{
  "id": 1, "date": "2026-10-05", "name": "AI 구독", "category": "sub", "amount": 29000,
  "shop": "", "note": "", "recurring": 1, "items": []
}
```
필라멘트 · 부속품 지출의 `items` (구매 항목, TBD-31 · 33):
```json
"items": [
  { "id": 7, "color": 1, "part": null, "qty": 4, "amount": null, "total": 72000, "each": 18000,
    "name": "Bambu Lab › PLA Basic · 화이트", "unit": "롤", "spools": 4, "used": 1 },
  { "id": 9, "color": null, "part": 1, "qty": 200, "amount": 12000, "total": 12000, "each": 60,
    "name": "네오디뮴 자석 6×3mm", "unit": "개", "spools": 0, "used": 0 }
]
```
| 칸 | 쓰기 | 설명 |
|---|---|---|
| `date` | 선택 | 지출 날짜, 기본 오늘. 오늘 이후면 400 `오늘 이후 날짜는 넣을 수 없습니다.` |
| `name` | ✅ 필수 | 항목 (최대 100자) |
| `category` | ✅ 필수 | 분류 (위 9개) |
| `amount` | ✅ 필수 | 금액. 1 이상 정수 |
| `shop` · `note` | 선택 | 구매처, 메모 |
| `recurring` | 선택 | 반복 지출에서 넣은 줄이면 그 id. 같은 반복 지출을 같은 달에 또 넣으면 400 `{"recurring": ["이 달에 이미 넣은 반복 지출입니다."]}` |
| `items` | 선택 | 구매 항목 (아래). 비워도 저장 |

### 구매 항목 `items` (v2 TBD-31 · 33)
| 칸 | 쓰기 | 설명 |
|---|---|---|
| `id` | 수정할 때 | 기존 항목이면 그 id (그 항목으로 만든 스풀이 이어짐). 없으면 새 항목 |
| `color` | 필라멘트 지출 | 색상 id |
| `part` | 부속품 · 포장재 · 소모품 지출 | 그 분류와 같은 탭의 재고 품목 id |
| `qty` | ✅ 필수 | 수량 (필라멘트는 롤 수 — 정수만) |
| `amount` | 선택 | 이 항목 금액. 비우면 나눠 넣음 |
| `total` | — | 항목 금액 = `amount`, 비웠으면 (지출 금액 − 금액 적은 항목 합계)를 비운 항목에 나눔 (필라멘트는 롤 수대로). 소수 2자리 |
| `each` | — | 1개(롤)당 금액 = `total ÷ qty` (소수 2자리) |
| `name` · `unit` | — | 표시용 이름 (`회사 › 필라멘트 · 색상` / 품목 이름) · 단위 (`롤` / 품목 단위) |
| `spools` · `used` | — | 이 항목으로 만든 스풀 수 · 그중 사용한(사용 중 · 사용 완료) 수 (필라멘트). 스풀에서 지운 것은 빠짐 |

- 보내면 그 목록으로 맞춘다 — `id` 있는 항목은 고치고, 없는 항목은 새로, 안 보낸 기존 항목은 지운다. 안 보내면 그대로. 분류를 다른 것으로 바꾸고 `items` 를 안 보내면 구매 항목은 지운다
- 같은 색상 · 품목을 여러 항목으로 적어도 된다 (예: 화이트 9롤 180,000원 + 할인 1롤 10,000원)
- 저장하면:
  - **스풀** (필라멘트) — 롤 수만큼 스풀을 만든다: 상태 `재고`, 구매가 = 그 항목의 롤당 금액(원 단위 반올림), 구매일 = 지출 날짜, 번호는 다음 번호부터.
    **지출 → 스풀 한 방향, 차이만**: 롤 수를 늘리면 늘린 만큼 새로, 줄이면 줄인 만큼 그 항목의 `재고` 스풀을 번호 큰 것부터 지움.
    색상 · 금액 · 날짜가 바뀌면 그 항목 스풀 전부의 색상 · 구매가 · 구매일도 바꿈. 항목을 빼면 그 항목의 `재고` 스풀을 지움.
    "차이만" 이라 스풀에서 분실 · 불량으로 지운 것은 지출을 고쳐도 다시 생기지 않는다. 스풀에서 바꾼 것은 지출에 반영하지 않는다
  - **남은 수량** (품목) — 남은 수량 + 수량, 입출고 기록 `지출 · 항목` (`kind: buy`). 고치면 차이만, 지출을 지우면 되돌리는 기록 `지출 삭제 · 항목`
  - **평균 단가** (품목, v2 PL) — 이 지출에 있던 품목마다 지출 구매 항목 · 입출고 기록을 날짜순으로 처음부터 다시 따라가 `avg_price` 와 기록의 단가를 맞춘다 (지울 때도).
    필라멘트 원가 단가는 보유 스풀 평균이라 스풀이 생기거나 구매가가 바뀌면 저절로. 지출은 색상 · 품목의 등록 가격(`price` · `pack_qty`)을 바꾸지 않는다
- 400 (`{"items": [...]}`):
  - 분류가 필라멘트 · 부속품 · 포장재 · 소모품이 아님 `구매 항목은 필라멘트 · 부속품 · 포장재 · 소모품 지출에만 적어요.`
  - 항목마다 `[{}, {"part": [...]}]`: `색상을 고르세요.` · `품목을 고르세요.` · `포장재 탭의 품목만 고를 수 있습니다.` · `롤 수는 정수로 적으세요.` · `이 지출의 구매 항목이 아닙니다.`
  - 사용한 스풀이 있는 필라멘트 항목: 색상 변경 `사용한 스풀 2개가 있어 색상을 바꿀 수 없습니다.` · `재고` 스풀보다 많이 줄이기 `재고 스풀이 2개라 2롤보다 적게 줄일 수 없습니다.` · 빼기(분류 변경 포함) `{"items": ["사용한 스풀 2개가 있는 항목은 뺄 수 없습니다."]}`
  - 필라멘트가 아닌데 금액을 비운 항목이 둘 이상 `여러 가지면 항목마다 금액을 적으세요.` · 금액 적은 항목 합계 > 지출 금액 `항목 금액 합계가 지출 금액보다 큽니다.`

- 목록 순서: 날짜 최근순 (같은 날이면 나중에 넣은 것 먼저)
- **여러 줄 한 번에** (이번 달 반복 지출 넣기): `POST /api/v0/expenses/` 에 목록 `[{...}, {...}]` 을 보내면 201 + 만든 지출 목록.
  하나라도 틀리면 아무것도 넣지 않는다 (400 은 줄마다 `[{}, {"category": [...]}]`). 같은 반복 지출을 한 번에 같은 달로 두 줄 보내도 400
- 삭제 (204): 구매 항목으로 늘린 남은 수량은 되돌리고, 필라멘트 항목으로 만든 `재고` 스풀은 지운다.
  사용한(사용 중 · 사용 완료) 스풀이 있으면 409 `{"detail": "사용한 스풀 2개가 있어 삭제할 수 없습니다."}`

## 반복 지출 `recurring-expenses`
```json
{ "id": 1, "name": "AI 구독", "category": "sub", "amount": 29000, "day": 5, "start": "2026-06-01", "note": "", "expense_count": 5 }
```
| 칸 | 쓰기 | 설명 |
|---|---|---|
| `name` · `category` · `amount` | ✅ 필수 | 이름, 분류, 금액(1 이상 정수) |
| `day` | ✅ 필수 | 결제일 1 ~ 31. 그 달 말일보다 크면 말일로 넣는다 (화면 계산) |
| `start` | ✅ 필수 | 시작 달. 아무 날짜나 보내도 그 달 1일로 저장 (`2026-06-17` → `2026-06-01`) |
| `note` | 선택 | 메모 |
| `expense_count` | — | 이 반복에서 넣은 지출 수 |

- 목록 순서: 결제일순 → 이름순
- 지출을 저절로 만들지 않는다. 화면이 "결제일이 지났는데 이번 달에 안 넣은 것"을 보여 주고, 확인하면 위의 여러 줄 추가로 넣는다
- 삭제: 막는 것 없음 (204). 이미 넣은 지출은 남고 `recurring` 이 `null` 이 된다. 해지 달은 없다 (그만 낼 때는 삭제)

## 판매 `sales`
```json
{
  "id": 22, "date": "2026-10-23", "channel": "store", "order_no": "2026102389012",
  "items": [
    { "id": 41, "product": 1, "product_name": "분수 원판 세트", "qty": 2, "unit_price": 18900, "unit_cost": 3227, "amount": 37800 },
    { "id": 42, "product": 4, "product_name": "이름 키링", "qty": 1, "unit_price": 4900, "unit_cost": 191, "amount": 4900 }
  ],
  "packs": [{ "id": 7, "part": 3, "part_name": "OPP 봉투 15×20", "qty": 1, "unit_price": 17.8, "amount": 17.8 }],
  "shipping_received": 0, "fee": 2011, "shipping_cost": 3300, "note": "",
  "gross": 42700, "settle": 40689, "pack_cost": 18, "cost": 6663, "profit": 30726,
  "created_at": "2026-10-23T05:12:00Z"
}
```
| 칸 | 쓰기 | 설명 |
|---|---|---|
| `date` | 선택 | 판매 날짜, 기본 오늘. 오늘 이후면 400 `오늘 이후 날짜는 넣을 수 없습니다.` |
| `channel` | 선택 | 판매처 `store`(스마트스토어, 기본) · `direct`(직접 판매) · `etc`(기타). 그 밖이면 400 `없는 판매처입니다.` |
| `order_no` | 선택 | 주문번호 (최대 50자, 앞뒤 공백 제거). 비어 있지 않은데 이미 있으면 400 `이미 넣은 주문번호입니다.` 빈 값은 여러 개 가능 |
| `items` | ✅ 필수 | 제품 줄 `{product, product_name, qty, unit_price, unit_cost}`. 비어 있으면 400 `제품을 한 개 이상 넣으세요.` |
| `items[].product` | 선택 | 제품 id. 제품을 지운 줄이면 `null` — 이때는 `product_name` 이 있어야 함 (둘 다 없으면 400 `제품을 고르세요.`) |
| `items[].product_name` | 선택 | 팔 때의 제품명. 비우면 제품 이름을 복사. 수정할 때는 받은 이름을 그대로 보내면 팔 때 이름이 유지된다 |
| `items[].qty` | ✅ 필수 | 수량, 1 이상 정수 |
| `items[].unit_price` | ✅ 필수 | 단가 (0 이상 정수). 화면이 제품 판매가를 기본값으로 |
| `items[].unit_cost` | 선택 | 개당 원가 (SALE-05, **포장 빼고**). 화면이 저장할 때 원가 계산표 값을 원 단위로 반올림해서 보낸다. `null` = 원가 없음 |
| `packs` | 선택 | 주문의 포장 줄 `{part, part_name, qty, unit_price}` (SALE-06). 추가할 때 안 보내면 포장 없음 (직접 전달) |
| `packs[].part` | 선택 | 포장재 id (`kind: pack` 만 → 아니면 400 `포장재만 고를 수 있습니다.`). 포장재를 지운 줄이면 `null` + `part_name` (둘 다 없으면 400 `포장재를 고르세요.`) |
| `packs[].qty` | ✅ 필수 | 수량, 0 보다 큼 (소수 2자리) |
| `packs[].unit_price` | 선택 | 개당 단가 (소수 2자리). **보내지 않으면 포장재의 지금 단가를 복사**. 수정할 때는 받은 값을 그대로 보내면 팔 때 단가 유지. `null` = 구매가 없음 (0원으로 계산) |
| `shipping_received` | 선택 | 손님이 낸 배송비, 기본 0 |
| `fee` | 선택 | 수수료. **추가할 때 보내지 않으면** 스마트스토어는 자동 계산(아래), 직접 판매 · 기타는 0. 보내면 그 값 그대로 (고친 수수료) |
| `shipping_cost` | 선택 | 판매자가 낸 택배비 (주문별 이익 참고용), 기본 0. 화면이 설정의 SET-08 을 기본값으로 |
| `note` | 선택 | 메모 |
| `items[].amount` · `packs[].amount` · `gross` · `settle` · `pack_cost` · `cost` · `profit` | — | 판매가(단가 × 수량) · 포장 금액 · 판매가 합계 · 정산 금액 · 포장비 · 원가 합계(제품 + 포장) · 주문별 이익. 원가 없는 제품 줄이 있으면 `cost` · `profit` 은 `null` |

- **줄 저장**: `items` · `packs` 를 보내면 그 목록으로 통째로 바꾼다 (줄 `id` 가 바뀐다). 보내지 않으면 줄은 그대로 (`PATCH {"note": "..."}`).
  하나라도 틀리면 400, 아무것도 바뀌지 않음
- **재고 빼기** (STOCK-04): 추가하거나 `items` · `packs` 를 보내면 부속품(제품의 사용 부속품 × 수량)과 포장재(포장 줄)를 남은 수량에서 뺀다.
  이미 이 판매로 뺀 만큼과 비교해 **차이만** 기록한다 (입출고 기록 `판매 · 이름 키링 외 1`, 날짜는 판매 날짜). 남은 수량이 모자라도 막지 않는다
- **수수료는 수정할 때 다시 계산하지 않는다** — 화면이 판매가 · 배송비를 바꾸면 새 수수료를 함께 보낸다 (`다시 계산`)
- 삭제: 줄도 함께 삭제 (204). 이 판매로 뺀 부속품 · 포장재는 되돌린다 (기록 `판매 삭제 · …`)
- 목록 순서: 날짜 최근순 (같은 날이면 나중에 넣은 것 먼저)

### 계산 (참고)
```
판매가 합계 gross   = Σ items.unit_price × qty
수수료 (자동)       = (gross + shipping_received) × (원가 설정 fee_order + fee_sales)%, 원 단위 반올림
정산 금액 settle    = gross + shipping_received − fee
포장비 pack_cost    = Σ packs.unit_price × qty, 원 단위 반올림   (단가 없는 줄은 0)
원가 cost           = Σ items.unit_cost × qty + pack_cost         (원가 없는 제품 줄이 있으면 null)
주문별 이익 profit  = settle − cost − shipping_cost
```

## 손익 `GET /api/v0/pl/`
```json
{
  "months": [
    { "month": "2026-09", "gross": 127700, "shipping": 3000, "fee": 2152, "sales": 2,
      "spool": 40000, "spools": 2, "spools_unpriced": 0, "parts_used": 1840, "parts_unpriced": 0,
      "expenses": { "invest": 0, "filament": 108000, "part": 0, "pack": 22000, "supply": 0,
                    "sub": 44000, "sell": 81500, "tax": 0, "etc": 0 } }
  ]
}
```
| 칸 | 설명 |
|---|---|
| `month` | `YYYY-MM`. **기록(판매 · 지출 · 사용 시작한 스풀)이 있는 첫 달부터 이번 달까지** 오래된 달부터, 기록 없는 달도 0 으로. 기록이 하나도 없으면 이번 달 하나 |
| `gross` · `shipping` · `fee` · `sales` | 그 달(판매 날짜) 판매가 합계 · 받은 배송비 · 수수료 · 판매 건수 |
| `spool` · `spools` | 그 달에 **사용 시작한**(`opened_at`, 서울 시간 기준 달) 스풀의 구매가 합계 · 개수. 구매가가 없으면 색상 가격 → 필라멘트 가격 |
| `spools_unpriced` | 그중 세 가격이 모두 없는 스풀 수 (0원으로 들어감) |
| `parts_used` · `parts_unpriced` | 그 달 부속품 · 포장재 **쓴 만큼**: 입출고 기록 중 판매 · 조정(처음 수량 빼고)의 −수량 × 그때 단가 합계(원 단위, 조정으로 늘면 줄어듦) · 그중 단가가 없던 기록 수 |
| `expenses` | 그 달(지출 날짜) 지출 분류별 합계, 9개 분류 모두 (없으면 0). 장비 · 필라멘트 · 부속품 · 포장재도 그대로 (현금 기준 · 두 기준 차이용) — 어느 기준에 넣을지는 화면이 고른다 |
